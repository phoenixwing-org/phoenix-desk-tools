# Phoenix Desk Tools 安装说明

- 项目主页：<https://gitee.com/phoenixwing/phoenix-desk-tools>
- VS Code 扩展：<https://gitee.com/phoenixwing/kt-auto-code>
- 共享框架：<https://gitee.com/phoenixwing/phoenix-wing>

## 1. 先选择使用方式

Desk Tools 与 KT Auto Code 共用 Phoenix Wing 中的代码生成算法、状态契约和 Web UI 组件，但两者是可独立使用的产品，不要为了使用其中一个而强制安装另一个。

| 使用方式 | 适合用户 | 主要特点 |
| --- | --- | --- |
| **KT Auto Code** | 已在 VS Code 中开发 C++/CAA/Codegen 的用户 | 代码生成、预检、Apply、Problems 和源码编辑保持在同一编辑器内；纯 TypeScript 能力可单独运行。 |
| **Desk Tools Web** | 需要独立的本地工作台或便于调试前后端的用户 | 浏览器界面 + 本地 Node API；覆盖 CAD 索引、BOM、CAA 和 Code 工具。 |
| **Desk Tools Tauri** | 希望将同一工作台作为本地桌面应用使用的用户 | 与 Web 版共用界面和 Node API；Rust 只承担 Tauri 窗口与 sidecar 生命周期。 |
| **KT Auto Code + Desk Tools** | 编辑器工作流与 CAD/桌面工作台都需要的用户 | KT Auto Code 保持编辑器体验；需要 Desk 本地能力时，通过服务登记发现并复用唯一的 Desk API。 |

三端的边界是：可共享的算法和 UI 放在 Phoenix Wing；VS Code 命令、编辑器、Problems 与扩展生命周期属于 KT Auto Code；CAD 业务、本地 API 与 Tauri 生命周期属于 Desk Tools。Web 和 Tauri 不应同时竞争启动两份 API；它们发现已登记的兼容服务时应直接复用。

## 2. 运行环境

从源码运行 Web 或 Tauri 版需要：

- Node.js 当前 LTS；
- 由根 `package.json` 锁定的 pnpm 9.15.9；
- 默认本地开发需要与 `phoenix-desk-tools` 并列的 `phoenix-wing`；
- 只有 Tauri 开发/打包需要 Rust stable 和 Tauri 2 CLI。

当前 Web/API 主链路不需要 Python 虚拟环境。FreeCAD 或 SolidWorks 是使用相应业务功能时的可选外部引擎，不是启动 Desk Tools 的前置条件。

## 3. 获取源码与安装依赖

标准开发目录：

```text
phoenix/
├── phoenix-desk-tools/
└── phoenix-wing/
```

```bash
mkdir phoenix
cd phoenix
git clone https://gitee.com/phoenixwing/phoenix-desk-tools.git
git clone https://gitee.com/phoenixwing/phoenix-wing.git
cd phoenix-desk-tools
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm install --frozen-lockfile
```

`pnpm wing` 找不到并列 Wing 时会停止，不会静默回退到 npm 包。非标准目录可显式设置 `PHOENIX_WING_ROOT=/absolute/path/to/phoenix-wing`。不要使用 `pnpm link`，也不要把依赖改为 `link:`、`file:` 或 `workspace:`。

## 4. 启动 Web 开发版

```bash
pnpm dev
```

上面的命令固定使用 Registry Wing；需要联调刚修改的并列 Wing 时改用 `pnpm wing`。

启动日志会显示真正的 UI 和 API 地址。默认从以下端口开始协调：

- Web UI：`http://localhost:49373`；
- Desk API：`http://127.0.0.1:48375`。

UI 端口被占用时启动器会选择下一个可用端口。Desk API 则使用服务登记和进程级原子锁：发现已启动的兼容 API 时复用，不通过“换一个端口”再启动一份。详见 [Desk API 单实例与多宿主发现](../platform/Desk-API单实例与多宿主发现.md)。

需要对照 Registry 中已发布的 Wing 精确版本时，使用：

```bash
pnpm dev
```

## 5. 启动 Tauri 桌面版

首次安装 Tauri CLI：

```bash
cargo install tauri-cli --version "^2.6" --locked
```

开发模式：

```bash
pnpm tauri:dev
```

Tauri 会自己启动 Web 前端；发现兼容的 Desk API 时复用，否则启动自己的 Node sidecar。不需要事先另跑一份 `pnpm dev`。完整打包和产物验收见 [Tauri 构建启动与验收指南](../tauri-构建启动与验收指南.md)。

## 6. 自检与常见问题

```bash
pnpm wing:check-local
pnpm test:local-wing
pnpm build:local-wing
pnpm verify:wing-dependencies
```

如果提示 `vite/bin/vite.js` 或 `tsx/dist/cli.mjs` 不存在，说明依赖安装不完整：

```bash
pnpm install --frozen-lockfile --force
```

如果提示端口占用，先查找 PID，再只结束对应进程：

```bash
lsof -nP -iTCP:49373 -sTCP:LISTEN
kill <PID>
```

界面使用方法见 [桌面工具使用说明](桌面工具-使用说明.md)，快速点检见 [快速开始](快速开始.md)。
