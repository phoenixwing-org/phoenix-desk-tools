# 维护已有 FreeCAD 图纸

文件详情的“整理已有图纸”先预览，再应用：保留当前图框文字、尺寸和布局，规范页面及 Link 标签，调整 3D 视图轴测/Fit，更新页面缩略图与 PDF。当前支持单页独立 Drawing，遇到多页或目标冲突保持原文件。

批量入口：`pnpm -C server exec tsx scripts/maintain-drawings.ts manifest.json --preview report.json`，确认清单后改为 `--apply`。清单为数组，每项含 `workspace`、`rel`，可选 `destination`、`material`、`export_pdf`。项目路径由调用方提供，不写进源码。未指定材料使用工作区默认值，明确候选材料不自动替换。`--preview` 不初始化原生门禁；`--apply` 使用与普通 Desk 服务相同的固定登记命名空间及 `native-freecad-v1` 持久门禁，不能另选目录绕过已有任务或未知残留。CLI 的接线回归采用 mock，不替代真实原生保存重开验收。

## 图框丢失的已知陷阱

1. 缩略图只是独立 PNG。图框在预览中出现，不证明最终 FCStd 能加载图框。
2. FCStd 内部 ZIP 顺序不能打乱。FreeCAD 的 `XMLReader::readFiles` 仅向前匹配已登记资源；删除条目后追加到末尾可能使该资源永远跳过。重命名应保留原槽位。
3. FreeCAD 原生 ZIP 可能使用未标记 UTF-8 的中文名称。依据 XML `FileIncluded` 精确匹配，必要时同步改为 ASCII 内部名；不能把乱码名称当新名称写回，也不能改 SVG 内容来掩盖加载错误。
4. 缩略图写入之后，再用独立 FreeCAD 打开最终文件，检查内嵌 SVG 实际落地、内容散列、标题栏与外链。验证只放在重打包前会漏掉问题。
5. TechDraw 有异步视图计算。等待剖面与尺寸准备完成再导出；初开时空剖面或零尺寸不能当最终输出。
6. 已打开的用户文档可能仍持有旧内容。保护未保存编辑后重开；不要将旧窗口保存覆盖磁盘修复版。

实现位置：`server/src/lib/fcstdArchiveNames.ts` 统一维护资源名称与顺序；`drawing-research/maintenance.ts` 在最终发布前执行原生重开验证。缩略图写入器使用相同资源处理。通用回归测试覆盖未标记 UTF-8、条目顺序、缺资源、外链变化和目标冲突。

原理依据：[FreeCAD XMLReader::readFiles](https://github.com/FreeCAD/FreeCAD/blob/main/src/Base/Reader.cpp)。

## 字体与工程符号

字体、纸面字高、符号和引线样式均属于图纸配置。机械尺寸可用已安装的 `osifont`；直径字符使用 `⌀`（U+2300），不要把希腊字母 Φ/φ 当直径。字母 Ø 应先确认标注意义再统一，不能全局替换普通文字。

水平文字配斜向直径引线时，FreeCAD 的 `StandardAndStyle = ISO Referencing` 与字体同样重要；改字体不等于改排布。字高使用纸面毫米，依工作区配置和图幅选取。

中文备注/标题栏检查实际可用的 CJK 字体，不能只检查属性字符串；跨平台字体名称可能不同。校验本机渲染和导出 PDF，记录替代字体，不把自动回退当作合格。

尺寸错误 `2D references are corrupt` 独立于图框加载及字体问题。定位文件和节点，按几何证据修复引用，不用固定显示数值遮盖错误。

## 图纸批量网页

入口：工具 → CAD 批量工具 → 图纸批量（`?page=drawing_batch`）。不依赖 CAD 索引；按当前工作空间显式选择目录，默认只扫描该层，递归需勾选。点开头的文件/目录、缓存目录和符号链接不参与批量修改。

两个可折叠 Block 独立工作：

- **检查与修复**：只读预览，逐文件、逐问题勾选。空标题栏、明确默认标签、同目标相对链接、精确资源名称及选中纸面对象的隐藏状态可提出修复；人工文字、材料冲突、多页、未知尺寸语义或几何引用须人工处理。`ShowFrames=false` 不是图框缺失，不自动改它。隐藏外层模型链接不等于缺图；源容器的实体全部隐藏仅提示，不显示源草图或历史节点，也不保存源 3D。
- **研究新稿**：从可确定主实体的零件生成，不覆盖已有 Drawing/PDF/记录；占位时生成带“初稿”序号的新文件。默认允许无参考 PDF 出图；取消“无参考 PDF 也生成研究稿”才筛选有可核对候选的零件。同编号/版本 PDF 仅为参考身份候选，未读取工程要求，不代表生产审批。总成仍须人工选择方案，不在此版本自动生成。

资源名称恢复仅支持按 `FileIncluded` 唯一证明的已覆盖编码形式。更复杂的多重错误编码链列为人工处理；名称匹配失败不等于已证明资源内容丢失。

纸幅默认自动，也可固定 A4/A3/A2/A1/A0 或明确选择模板。自动模式在独立原生进程中读取三个真实 1:1 完整曲线投影，以与生成器相同的布局和标题栏安全区选择纸幅：先依次尝试 1:1、1:2、1:5、1:10 下的 A4/A3/A2，全部不适配后才尝试 A1/A0；明确比例不自动降档。预览显示并冻结实际纸幅、比例、模板和依据，生成不再换纸。自动只接受实际 FreeCAD 安装绑定的 ISO5457 advanced 同族，缺少 A4/A3/A2 或未知目录列人工，不回退 A4；明确模板保持固定。含装配/Joint 源依赖的新稿在单件/批量、自动/固定纸幅均列人工并在执行前重查，正式新稿尚未具备与只读预览相同的装配求解/Frame 保护。

无原图研究稿不推断生产公差、材料物性或工程要求。检查与修复的尺寸字体规范默认建议 `osifont`；中文注释修复须显式指定并验证实际字体，不把回退当合格。新稿的字体和符号仍需逐页纸面核对。只有明确确认直径语义的 Ø 才可建议改为 ⌀，未知整数枚举及坏 Edge/Vertex 不自动猜测。

研究新稿的自动比例优先 1:1，不默认放大；用各视图实际完整曲线的投影包围盒和固定纸面标注余量安排两列或两行，再选择能容纳的最大常用比例。自动宽/高标注仅在真实索引顶点覆盖完整曲线边界、原生尺寸值匹配该轴跨度时保留；圆弧或保守包围盒不满足条件则逐轴跳过，提示人工补直径或外缘标注。最终重开再次读取实际曲线、比例、布局和尺寸，不能只复用报告中的数值。固定余量不等于所有文字、箭头的精确碰撞检测，也不代表工程尺寸覆盖完整。

计划有效期：校核 10 分钟、研究新稿 30 分钟。应用前需确认并重新核对 Drawing、源依赖、模板及采用的参考 PDF 散列；文件变化需重做预览。勾选修复更新页面缩略图和 PDF，保留备份；所有 ZIP 后处理完成后再独立重开核对图框、链接位姿和尺寸，校验失败不发布替换。原生任务串行；取消仅结束本工具拥有的子进程，未执行项有独立结果，单文件失败不妨碍后续文件。错误和待审提示自动打开 Bottom 运行日志。

新稿原生错误附执行阶段、净化后的有界错误摘要及本任务日志路径。生成/验证分别保留最多 8192 字节的 UTF-8 日志尾，阶段记录只在确认子进程身份后写入。失败先落报告，暂存清理或文档关闭异常不会直接跳过退出调度；超时仍只终止本任务子进程，等待退出后释放串行锁。阶段用于定位卡点，不把超时本身猜成几何错误。

已有图纸修正使用相同的阶段归属与有界诊断原则，维护及最终验证各自记录日志；每个原生进程仍为 180 秒上限，新稿仍为 10 分钟，未通过延长超时掩盖故障。修正写入的页面 PNG 需通过完整性、解码、非单色与原生散列检查，最终 ZIP 再验证内嵌 PNG 及暂存文件散列，验证后变化不发布。

每个文件最多选择 100 个精确修正项，整批文件上限仍为 500；超过上限不消耗预览，可减少勾选后重试。旧图材料只有源模型非空属性或用户显式配置才可提出补全；两者均无证据时仅提示人工确认，不自动写入推测牌号。研究新稿的材料建议不等于旧图修复依据。

应用修复前，用户须保存未保存编辑，并在自己的 FreeCAD 中关闭所选目标图纸，避免旧窗口再次保存覆盖修复；不用关闭整个 FreeCAD。研究新稿和部分输出均需人工复核，不以成功状态代替工程验收。

### 关节引用与删除保护

图纸维护的相对外链保存流程会暂断并重绑本图纸的 `App::Link`，这不等于删除零件，但也不能假定对装配约束无副作用。当前不提供自动删除 Joint/Joints/零件或 Rigid 往返切换：

- 待写图纸本身含 `Assembly::AssemblyObject`、`Assembly::AssemblyLink`、`Assembly::JointGroup`、`Assembly::Joint`，或任何对象带 `Reference1`/`Reference2` 属性时，在计划和原生开文档前拒绝自动整理，保持原件；未知关节格式也不尝试猜接。
- 原生打开后，任何本图纸 `App::Link` 被非 TechDraw 对象引用时，在修改/重绑前拒绝，并指出 Link 与引用者；最终 ZIP 重开再次检查。普通独立图纸引用外部 ASSY 仍可维护，源模型只读、只核对指纹，不因此改写装配。
- 隐藏、空组、无 Shape 或没有失联提示都不证明可安全删除。装配的“检查 → 预览 → 修正/更新”仍是独立待办，须保留内部对象身份、关节两端完整子路径、组归属、刚柔性与位姿；不能用删除 Joint 清除告警。现有 Primary/数据库诊断仅覆盖明确空端和缺失本地对象，不是外链/子元素/求解完整性证明。

依据：[FreeCAD AssemblyLink 源码](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/Assembly/App/AssemblyLink.cpp) 的 Rigid 变化路径会处理接地、放置及父装配关节引用，因此不能把切换往返封装成无副作用的通用修复。本地版本行为仍须独立验证。

### 协作验收契约

服务前缀 `/api/cad/drawing-batch`；每次调用显式带 `workspace` 查询参数，模板列表只读。HTTP 不接收任意原始补丁，仅接受服务器预览签发的计划和勾选 ID。

| 调用 | 用途 |
| --- | --- |
| `POST /audit/preview` | 目录、递归与字体规范，只读问题/建议 |
| `POST /audit/apply` | `plan_id`、文件及问题 ID、`confirmed:true` |
| `POST /generation/preview` | 目录、图框、纸幅、比例、`allow_without_pdf`（默认 true） |
| `POST /generation/start` | `plan_id`、候选 ID、`confirmed:true` |
| `GET /jobs/:id`、`POST /jobs/:id/cancel` | 工作空间归属的进度及显式取消 |
| `GET /templates` | 安装图框或显式图框目录清单 |

公共单元夹具独立构造，不复刻用户工程。原生公开样例验收另行记录：空字段补全、人工冲突保留、资源原槽位修复、图框隐藏精确恢复、字体缺失拒绝、两文件串行及失败继续、取消不关闭用户 FreeCAD、占位新稿不覆盖，并检查最终 FCStd/PDF/缩略图三个对象。原生验收未完成时，不宣称网页测试已证明图纸可用于生产。

### 当前验证结论

2026-10-15：Registry 与本地 Wing 模式均通过 170 项后台定向测试、40 项网页测试，以及类型、构建、架构、文档和 Wing 依赖边界检查。FreeCAD 1.1 实测发现尺寸对象不存在 `Measurement` 属性，已统一使用 `getRawValue()`；生成及独立重开均等待实际投影边和尺寸稳定，再核对真值，不用缓存常数替代。

首轮纸面复核另发现空白缩略图、默认节点标签、研究稿说明遮挡标题栏，不能据任务成功状态认定视觉验收通过。新稿已改为实际页面 SVG 渲染白底 PNG，校验固定路径、散列、PNG 完整性及非单色，再写入 ZIP 原条目位置并独立原生重开。页面及源 Link 只规范显示标签，不改内部节点 Name；身份字段不完整时明确使用“研究稿”，不把 `.ASSY`、`.v2` 当版次，也不虚造版本。

新稿布局为说明预留标题栏上方空间，仅对新建稿清空已确认的库存模板占位键/值；旧图修复的人工文字、材料和布局边界不变。实际投影包围盒排版与尺寸跨度校验已经修正，不能将圆弧的局部顶点距离当作整体跨度。缺少阶段报告的历史超时仍保持未确认，不以其它样本通过替代其复验。

诊断补齐后，另在仓库外独立构造长方体、长管、短环进行无 PDF 原生验收，加一次重复生成，共四份新稿均完成生成及所有 ZIP 后处理后的独立重开。实际尺寸与完整曲线跨度逐项匹配；短环圆端面两个轴明确跳过并提示人工补标，没有以局部点距假充整体。PDF 和内嵌 PNG 分开目视核对；重复生成使用“初稿02”，三份源文件和九个旧输出散列均未变化。该结论只覆盖这些独立合成条件，不解释之前的单次超时，也不代表全部工程尺寸、字体或精确字框碰撞合格。原生失败仍按文件记录，不能用任务成功替代工程审核。

### 本轮增量验收（2026-10-15）

- 串行队列的验收条件包括：不存在字体时保留原件并报告失败，后续安全项可继续；标题栏、图框显示或编码资源名修复须经过全部 ZIP 后处理后的独立原生重开，备份与写前原件散列相同，源 3D 字节和外链位姿保持，未选问题不顺带修正。
- 比例验收须分别检查自动比例、明确比例与无法容纳纸幅时的安全拒绝；圆端面的不可靠顶点跨度跳过并提示补直径／外缘尺寸。独立条件通过不解释历史无阶段记录的超时，也不证明历史输入散列相同。
- PDF 与内嵌 PNG 分别检查图框、标题栏、视图和已有有效尺寸，研究稿提示不得遮挡标题栏。纸面可见性不代表生产尺寸覆盖、审批完成或全部字体/碰撞合格；实际模型、图片、日志、映射和散列明细不得进入公开夹具。
- 网页的检查修正与研究新稿核心流程已接通；多页、总成自动出图、坏几何引用猜接、完整语义标注、材料物性及自动装配同步仍未交付。单文件详情的旧“整理”入口尚未完整展示回执中的逐条 warning/备份位置，不能将批量结果展示的验收外推到该入口。
- Joint 防护另有目标混合文档拒绝、未知引用属性拒绝、注释/CDATA 不误判、外部 ASSY 允许及非 TechDraw 入引用拒绝的独立合成回归。加入防护后，普通独立图纸副本再次完成原生整理及最终重开，源 3D 散列不变、备份与写前原件一致；不表示已完成装配约束自动修复。
- 本轮联合回归：Registry/LOCAL 各通过后台 20 文件 289 项、网页 7 文件 55 项；随后补齐空 `Assembly::Joint` 拒绝用例，最终维护相关 4 文件各 90 项通过。双端类型、Web/Server 构建、架构、文档和 Registry 精确依赖边界通过。参数化测试标题已去重。这是定向回归与上述原生验收，不是全仓 CI、安装器或发布放行。

### 真实引用、纸幅与源装配增量（2026-10-16）

### 对象故障状态与缓存投影保护

投影缓存仍可读取，不代表View有效。预检先检查View的原生 `Error/Invalid`，失效或状态接口不能确认时不采信缓存，整文件自动项关闭；稳定性同时比较实际尺寸和引用几何，不再仅看边数。独立合成样例以真实表达式错误复现了“View已Invalid，但原4条边及顶点仍可读”，修正后预览没有ready/patch，输入保留。

已加载的源Link/Joint记录明确故障标志及状态文字，与隔离打开后、首次工具重算前的基线比较；新增、消失或变化都拒绝继续写入。瞬态Touched不当作故障。原有错误不一概视为Frame损坏：只有目标、实际Frames、位姿和所需几何均能验证且保持时，才允许修改勾选的图纸字段，并在预览及完成警告明确“既有源对象故障保留、未修复”。保护条件通过不是源工程健康认证，也不表示未加载对象已逐一校核。

### 相机、线宽与自动纸幅增量（2026-10-17）

单件缩略图的轴测/Fit 使用确定性的 Coin 相机计算；不勾 Fit 时保留相机及原始宽高比，整图白边成方图，不裁切前景。Fit 使用完整像素边界，离散的单像素线也参与裁剪与边缘检查。旧图精确字段修复不调整相机，非精确整理才执行轴测/Fit。公开独立场景验证了透视 Fit、非零位姿链接、辅助包围盒节点恢复及原比例留白，源字节保持。
