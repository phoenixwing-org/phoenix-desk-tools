适用范围：Desk Tools 通用批量及修正任务；CAD 为首批接入领域，不限定未来业务类型。

目标是建立可保存多个批次、可反复预览、可追踪对象和 action 的统一管理。第一阶段实施本地 SQLite、服务驱动队列、管理页和应用级监控，以普通文件及 FCStd 已保存属性的只读采集验证；修改、修正、渲染和出图后续逐项接入，不把旧 HTTP 接口简单串起来。

## 本次复盘后的实施范围

采用适中的单机结构：SQLite 是真源，单服务串行 worker 消费持久队列，内存只负责唤醒；HTTP 带工作空间、请求幂等标识及事件游标，前后端共用纯契约。以后远程 Web 可沿同一契约增加认证、授权及 worker 管理，本期仍沿既有本机权限，不开放公网、Redis 或分布式调度。

第一阶段注册 `file.metadata`、`file.text-stats`、`cad.saved-properties`；2026-10-20 的 T1a 增加 `cad.saved-links` 与 `cad.saved-drawing` 两项窄摘要，形成五动作基线。T1b 增加 `cad.geometry-cache` 与整批 `cad.name-audit`，默认 V2 仍为这七项。V2 输入最多 200 个明确相对文件、8 个 action 实例，不扫描目录、不跟随 CAD 外链、不启动 FreeCAD、不写 CAD。T1c 的独立 V3 仅供显式 host 单文件保存 BRep 试点，Web 只读展示；不先做 DAG、写入自动重试或全部旧工具迁移。详见 [CAD 动作清单](../cad/CAD批量动作接入清单.md)。

隔离 V2 按 action-major 串行：action 实例按保存顺序执行，file 步骤在该实例内按冻结文件顺序执行，batch 每实例仅一次并包含完整输入。预览显示实际 file/batch 数量和 ready/blocked/not_applicable；缺失源的 SHA/bytes 为 null，不能用空 SHA/0 或首文件伪装整批。效果白名单仅 `read_file`、`read_cache`、`write_task_db`；缓存查询会创建/释放自有临时协调锁，不回收已有锁、不更新缓存，观察始终 `freshness: unverified`，历史 hash/stamp 不提供当前依赖 SHA 新鲜度证明。

存储冻结为 `.phoenix/batch-tasks.sqlite`，使用 Wing 同步 DB Adapter、DELETE journal 和短事务。schema3 为原 meta/task/plan/run/step/event 六表加 `desk_batch_native_attempt`、`desk_batch_native_event`，不改变 Wing workspace schema。V1/V2 先保存、核验原版逻辑备份，再同事务推进 schema；既有无任务元数据文件只读识别后拒绝接管。HTTP 幂等、防重复消费、queued run 同事务接纳；Native 终态、结果和事件同事务提交，定义变更不影响已接纳 revision。

关闭页签/浮窗不取消后台。取消是请求，确认安全停止才终态；已成功项保留。活 owner 或跨主机归属不明时拒绝接管，重启旧 active（含 queued）标 interrupted、旧计划失效，不自动重放。WASM 侧锁不按超时删除，残留时人工核对。独立版本化逻辑备份带校验和，只能恢复到空任务库，旧授权不恢复；不包含 CAD、主库、outbox 或外部输出。

参考成熟方案的语义而非引入其依赖：[Hangfire 持久入队与服务执行](https://docs.hangfire.io/en/latest/background-methods/calling-methods-in-background.html)、[BullMQ 幂等](https://docs.bullmq.io/patterns/idempotent-jobs) 和 [协作取消](https://docs.bullmq.io/guide/workers/cancelling-jobs)。本地队列不照搬失锁后的自动重投写入，未来写动作仍需发布不确定与 reconcile 验收。

### 当前交付与后续边界

已交付纯共享契约、Repository、服务端队列、白名单 Adapter、管理 View 和应用级 Wing 监控。定义可新建、复制、按 revision 编辑和归档；保存与运行接纳分别使用稳定幂等标识，响应未确认不会静默重复创建。文件清单可手工填写或从当前工作空间工作集复制快照；预览不执行领域 action，确认才排队。V2 预览会读取冻结来源及只读缓存投影，执行仍须前后重验；结果、排除原因与事件保存在任务库，部分失败不冒充全部成功。

首期隔离样本验收包含两项排队运行、对象/动作观察结果、页面刷新和 Primary 停靠；真实服务重启保留已完成历史，运行中及 queued 项变为 interrupted，未消费预览失效。独立文本与单对象 XML 样本的源指纹保持不变，未操作个人工程或调用 Native。

下文是完整产品方向，不代表全部已实现。首期未交付跨页购物车按钮、自动约两秒飞入停靠动效、网页恢复入口、远程 worker、统一任务 CLI/任意脚本及复杂 CAD 动作。当前监控支持手动浮出/停靠；逻辑备份可从页面导出，恢复仅有后端空账本入口且不恢复执行授权。下批优先接入静态诊断和显式目标的缓存/测量；旧工具暂保留原流程。

V2 host 对 canonical prepared payload 计算 digest，并验证完整 envelope、注册动作和冻结 sources/resources。`isCurrentPlan` 等 typeguard 只辨版本，不授予权限；新确认必须带 `protocol_version: 2`。旧浏览器恢复指针可以按原 requestId 查询历史，没有 run 时重新预览，不给旧计划补版本后重发。同 requestId/计划/摘要只执行一份在途接纳；服务关闭先中止并等待这些请求，再关闭任务库，避免查询 404 后原请求仍迟到提交。

迁移前先生成、核验并保留原 v1 逻辑备份；备份失败、目录/文件身份不符或活 owner 阻止推进 schema，保留旧状态。旧终态快照/结果/digest 只读保留，旧 fresh 计划失效，旧 active/queued interrupted，不恢复执行权限。恢复仍只允许空任务库，先核原备份 checksum，再检查新旧版本与完整目标，不导入 owner 或资源授权；旧程序拒绝新协议库。该迁移只涉及 Desk 任务库，不提升 Wing workspace schema13。

缓存 action 只观察已有记录，missing/unknown/invalid 都有明确原因，不能伪报已测得尺寸；读取失败冻结为 blocked。整批名称分析只比较冻结 files[]，不调用递归/保存偏好入口，不合并、删除或猜测 variant。该 V2 验收不开放 Native、业务缓存写入或 CAD/输出写入；P0 86 项回归仅为纯输入核验，没有 Native 或来源新鲜度证明，详见 [受控执行契约](../cad/CAD后续能力实施规划.md#t1c-t2-受控执行契约)。

## 一 核心决策

1. **一个通用管理层，多个领域 Adapter。** Desk 管理任务、计划、执行、记录和恢复；CAD、改名、转换等 Adapter 管理各自算法及安全规则。Wing 复用承载、展示和数据库适配能力，不承载 CAD 业务执行。
2. **任务定义与某次运行分开。** 用户可以修改、复制任务；已接纳运行的对象、action 版本、参数和授权范围冻结，修改定义只影响下一次运行。
3. **当前只读顺序与未来写入分期区分。** 隔离 V2 当前是 action-major，file 步骤按冻结清单、batch 每实例一次。未来组合写入先全批预检，再按依赖处理已授权修改，最后获取最终数据、归并缓存/索引；不能用当前只读循环代替未来依赖规划，顺序必须在预览可见。
4. **DB 是执行状态真源。** 浮窗、Primary、完整管理页和未来脚本查询同一个 run；关闭页面、停靠和动画不启动、取消或完成任务。
5. **先接读及缓存任务，再接受控写入。** 质量计算、链接修正和装配同步分别补能力，不能因为有统一按钮就宣称已经可以安全执行。
6. **网页与未来脚本共用计划和执行服务。** 不把函数、任意 shell 或可长期复用的写入授权存进 DB，也不导出第二套未经同等验证的算法。

| Wing 停靠及进度 | Registry 0.8.0 已公开浮窗/Primary Tool 组件，Desk 有实际装配样板 | 没有公共购物车业务或飞入动画；旧任务 store 不是服务端运行账本 |

### 优先整改风险

- 旧 `useAsyncProgress.cancel()` 在取消 HTTP 请求失败后仍可本地标记 cancelled；Wing 旧 store 也有同类行为，并在刷新时把 running 变为 orphaned。新管理器不能继承这些状态作为权威，取消失败仍须查询后台状态。
- 旧链接择近逻辑不能作为新自动修复依据。歧义必须人工确认，不能按 Label、basename 或路径距离猜接。
- 同一固定宿主 scope 的原生入口已有持久互斥；不同 Registry/state scope 的跨宿主协调尚未验收，浏览器 profile 的 Native 保持禁用。不能据此宣称任意页面、CLI 和脚本之间均已互斥。
- “提取已有缩略图”与“重新渲染并写 FCStd”必须是两个 action；“读材料牌号”与“赋物性/算质量”也必须分开。

## 三 产品入口与交互

### 批量任务管理页

新增独立“批量任务管理”View，管理当前工作空间的多个任务。提供新建、复制、编辑、预览、准备运行、历史、重试及归档；草稿删除不删除 CAD、输出或备份。运行中编辑生成新的定义 revision，不改变正在运行或已排队的快照。

主区展示任务定义和运行历史；详细运行可按文件、action、状态筛选。V2 按实际 file/batch 步骤呈现，整批显示全部 subjects，按其中任一文件筛选都可命中；旧 V1 文件明细继续只读显示。成功、失败、阻塞、不适用、取消及结果未确认分别呈现。执行状态与人工验收状态分开，图纸执行成功仍可待工程审核。

### 购物车与 Primary

1. 树、目录、图册、详情及问题列表提供“加入批次”。购物车接收通用 SubjectRef，不直接调用执行服务；保存成功后更新数量，失败不先显示已加入。
2. 购物车对应当前工作空间的一个活动草稿，允许切换到其它已保存任务。零件数、实例数、文件数和最终执行目标数分别显示，不能混计。首版不在一个 run 中混合工作空间；领域所需外部目录需显式根目录授权。
3. 优先复用工作集作为输入来源，导入时复制选择快照；工作集后续改变不修改已预览计划。零件默认仅带入明确的主模型，是否包含关联图纸/引用宿主须在预览中明确，不能自动展开所有关联文件。
4. 浮窗及 Primary 共用一个 Controller/store。使用 Wing 的应用级 Dockable Tool；`closed / floating / primary` 是呈现位置，不是任务状态。关闭 X 仅隐藏工具，不取消运行。
5. “准备运行”打开摘要预览，展示 action 列表、有效顺序、对象/文件数量、预期修改、排除/阻塞项、材料来源、备份策略及风险。“确认运行”才接纳 run，不重复启动已有 run。
6. 后台确认 run 已接纳后，先显示运行摘要，默认约 2 秒后以短动效停靠到 Primary。后台立即运行，不等待动画。快速完成、立即失败、用户正在操作/固定浮窗或减弱动画模式下不强行收起；错误保持可见并打开 Bottom。
7. Primary 展示当前工作空间的活动任务、阶段、对象/action 数量、取消状态和最近问题，支持浮出及打开完整管理页；停靠时同步请求显示原先隐藏的 Primary。页面卸载、工作空间切换和网络暂断不能丢任务；重新查询 DB 后恢复投影，不自行判定完成。

Wing 已具备 `PnwDockableToolWindow`、`PnwDockablePrimarySection` 及 `pnwReduceDockableToolState`；Primary 首尾停靠可复用。购物车内容与可选转移动效由 Desk 实现，不依赖完整 View Portal 的本地新增接口，不另造 Wing 的第二套浮窗框架。

## 四 输入身份与 action 注册

### 输入对象

SubjectRef 至少区分普通文件、零件主模型、图纸、宿主内对象和装配实例。保存工作空间/授权根别名、相对路径、内部对象 Name、宿主路径、实例路径及来源；Label 只作显示。

Rigid 是宿主内 AssemblyLink 实例属性。同一源模型在不同宿主或实例中不能按 rel 去重合并。纯文件读取可以复用相同文件/对象的测量结果，但质量汇总的实例数量与实例级修正目标必须保留。改名后只能通过本次已验证回执更新目标映射，不能按新相似文件名重新寻找对象。

### ActionDescriptor 与 Adapter

每个 action 有稳定 key、参数 schema 版本、实现版本、标题、适用输入类型、scope（逐对象/逐宿主/整批）、依赖、阶段、效果分类、资源声明、取消能力、重试策略和验收要求。用户的 action 实例另有 instance_id、顺序、启停及参数；同一 action 可按需要有多个不同配置实例。

效果至少区分：只读 CAD、写任务 DB、写业务缓存、写 CAD、改路径、创建输出、影响外链或全局偏好。读 CAD 并写测量缓存不能在 UI 中简称“完全不写入”。

注册表由服务端白名单代码提供；DB 记录用户选中的 action、参数、顺序、版本及每次结果，不保存可执行函数。Adapter 提供 validate、preview、declareResources、execute、verify、reconcile；HTTP、View 和调度器不得复制领域算法。

| 拟接入 action | 首期边界 | 后续工作 |
| --- | --- | --- |
| `cad.properties.inspect` | 读取已保存属性和材料字符串，写观察结果，不改 CAD | 来源冲突保留，材料赋值另立 action |
| `cad.geometry.bounds` | 确定主实体，读取 XYZ 边界盒，写缓存 | 从显式选择接入底层 reader，补取消；不经产品高层接口扩大范围 |
| `cad.thumbnail.extract` | 提取/复用已有 PNG，写图片缓存 | 仅所选目标，不隐式展开产品引用 |
| `cad.links.inspect` | 候选及歧义报告，不自动修复 | 去掉预览写偏好的副作用，或明确分离保存设置 |
| `cad.assembly.inspect` | Rigid 与 Joint 窄范围诊断 | 未验证状态明确呈现，不把柔性判错 |
| 图纸精确修正及新稿 | 复用已验执行器、计划与验收条件 | 适配到统一 run，避免内外两套队列同时调度 |
| `cad.thumbnail.regenerate` | 第一阶段只声明能力，不直接开放通用写批量 | 改为自有隔离进程，补票据/CAS/取消/最终验证，不改用户 GUI 全局偏好 |
| `cad.links.repair` | 未满足安全条件前禁用 | 唯一目标、宿主对象和源/目标指纹、精确补丁、备份与重开 |
| 材料物性与质量 | 先读取/核对来源，未知值为空并带原因 | 有效体积、密度/单位、材料映射版本及计算缓存 |
| `cad.assembly.refresh` | 保留为未开放能力 | 独立原生专项验证，不以 Rigid 往返切换或删除 Joint 实现 |

属性写入、改名、STEP/SW 转换、标签修正及离线导出以后按相同 Adapter 契约接入。不能为恢复通用任务管理而恢复已退役的 Code 业务，也不要求一次迁移所有批量工具。

## 五 调度顺序

### 默认策略

当前隔离 V2 只读实现采用 action-major；batch 每 action 实例一次，不乘以文件数。以下是 T1c/T2 的后续分阶段策略，不表示当前已开放混合读写。

整体按以下阶段组织：冻结范围与预检；确认计划；受控修改；最终读取/派生数据；缓存/索引归并与验收。阶段之间有屏障，阶段内按实际文件/宿主和资源约束调度。

只读 ZIP 分析可有界并行，原生 GUI 和写 CAD 默认串行并锁定真实资源。现有隔离执行器可以按文件逐个调用；首版不为“打开一次完成全部 action”合并已有进程或削弱独立重开验证。后续有明确收益及安全证明时才优化会话复用。

用户顺序仅调整互不依赖的 action；依赖拓扑及资源安全优先，预览展示最终顺序和调整理由。首版不做任意工作流编辑器，但计划编译必须检测缺少前置条件、依赖环和不支持的组合。

### CAD 例子

若选择链接修复、重新生成内嵌缩略图、材料/尺寸/质量采集：先分析全部目标和依赖；确认安全修改计划；对所选文件完成已授权修正和重开；在最后一次写 FCStd 后获取最终数据/缓存；末尾归并刷新必要索引。

未来重新采集的缓存须按完整来源与依赖指纹证明新鲜度。当前 `cad.geometry-cache` 只报告已有快照并始终 unverified；不能把 stamp 匹配当 SHA 新鲜。若先测尺寸再写内嵌缩略图，文件 hash 会改变，刚取得的缓存可能立即陈旧；没有经过验证的几何/外观分离指纹前不能忽略该变化。

跨文件引用变更需先取得全批计划，按依赖关系锁定源和宿主；不能当无关零件独立循环。整批索引刷新等 action 只执行一次，不对每个零件重复运行。某文件失败只阻止其依赖步骤，其余确认为独立的安全项继续；未知写入会阻塞受影响资源及下游，不继续猜测。

## 六 MVC 与宿主边界

| 层 | 职责 | 禁止承担 |
| --- | --- | --- |
| 纯 Model/契约 | SubjectRef、定义/计划/run DTO、action 元数据、状态转换、依赖编译、计数及查询投影 | Vue、DOM、HTTP、SQLite、进程或真实文件读写 |
| Repository | DB 迁移、事务、版本并发校验、事件及历史查询 | 执行 CAD 或把 JSON 当代码运行 |
| Application Service/Controller | 建批、预览、确认接纳、调度、取消、重试及协调资源 | 具体几何、改名、图框或链接算法 |
| 领域 Adapter/Host port | 文件安全、领域计划、原生进程、写入、验收、reconcile | 操纵 Vue 或依赖某个页面已挂载 |
| ViewModel/前端 Controller | API 编排、轮询/事件游标、草稿编辑、选择、错误映射和呈现偏好 | 决定后台任务已停止、持有唯一运行真值 |
| View | 任务列表、购物车、action 配置、预览、矩阵及 Primary 展示 | SQL、文件系统、直接 Native/RPC 或业务安全判断 |
| Wing | Dockable/Primary/进度/日志承载、纯展示工具及 DB adapter | Desk 的 action 注册、CAD 参数、文件权限和恢复策略 |

纯契约置于 Desk 内可供前后端消费的共享层，具体目录在实施阶段冻结；前端不直接 import server。新增 action 通常只增加 descriptor、Adapter、参数展示及测试，不要求修改通用状态机或 View 的条件分支。任务持久 store 在 Dockable 与页面生命周期之外；PagePrimary contribution 只作入口和投影。

## 七 数据库与记录模型

### 存储建议

推荐按工作空间建立 Desk 自有任务库 `.phoenix/batch-tasks.sqlite`，使用现有 DB adapter，独立 schema 版本和受控迁移；不提升或修改 Wing 冻结的 workspace schema13，不把高频事件塞入偏好 JSON 或测试 runtime-catalog。实施 M0 需冻结该存储决定及资源协调方式，再建表。

任务库不会自动进入现有工作空间恢复包：当前恢复仅处理主 workspace.sqlite 与 outbox。M1 必须同时交付任务库的一致备份/恢复或明确的独立任务备份入口，展示覆盖范围；不能把任务 DB 及外部输出/备份文件误称为已随主库恢复。SQLite journal/WAL 选择及备份一致性须单独验收，不照搬旧文件复制假设。恢复只恢复定义和历史，不恢复写入许可；旧 fresh 计划失效，非终态运行重新核对。

### 后续完整逻辑模型

下表是复杂任务的扩展模型，不要求首期全部分表；首期实际模型见本次实施范围，不能将下表当成当前均已交付。

| 表 | 记录内容 |
| --- | --- |
| `desk_batch_task` | id、名称、revision、启用/归档、版本化定义 JSON（输入引用及 action 实例配置）；定义可编辑 |
| `desk_batch_plan` | 只读预览、具体展开清单、依赖/效果、指纹、确认摘要 hash、失效时间与消费状态 |
| `desk_batch_run` | task revision、计划及冻结 spec、实现/配置版本、请求幂等 key、宿主/owner nonce、状态、取消请求、重试来源 |
| `desk_batch_run_item` | 本次实际对象/文件/实例、稳定 item key、顺序、来源指纹及目标身份，不依赖可变任务定义反查 |
| `desk_batch_run_action` | action instance/key、schema/实现版本、冻结参数、scope、有效顺序、依赖及效果 |
| `desk_batch_attempt` | 稳定 step key、item/action、attempt 编号、状态、开始/结束、错误码、输入/输出 hash、实际变化、发布及验证结果 |
| `desk_batch_event` | run 内单调 seq、状态变化和安全摘要；与对应状态更新同事务提交 |
| `desk_batch_artifact` | 输出、备份、日志、报告及观察结果引用，hash、发布/存在状态和所属 attempt |

Run 的 **spec 不可变，执行状态可受控变化**。task 的新版参数、工作集、模板、材料映射和 action 升级不得改写旧 run。未知 action 版本可查看历史，但不能静默换新版继续执行。逐 item/action 的尝试不覆盖历史；新输入、重试或核对结论有来源关系。

事务只覆盖所在 DB 的状态，不能假装同时回滚文件系统或另一业务库。执行前落意图、预期范围和输入证明；执行后验证并记回执。写文件或业务库已提交、任务回执尚未落库即崩溃，都要显示结果未确认并 reconcile，不得报为零输出或直接重做。禁止跨 Native 执行长时间持有任一库事务，也不以同时打开两库事务冒充跨库原子提交。外部日志有界存文件，DB 存索引/安全摘要，不无限保存完整 stdout。

### 生命周期与恢复

- TaskDefinition：草稿/可用/归档；不拿“running”当定义本身的唯一状态，一个定义可有多次历史运行。
- Plan：fresh、expired、invalidated、consumed；改选择/参数/范围使旧计划失效，沿用 Adapter 更严格的票据及数量门禁。
- Run：queued、running、cancel_requested、succeeded、partial、failed、cancelled、interrupted、needs_reconcile。人工审核状态单独保存，不能阻止查阅已完成回执。
- Step：pending、running、succeeded、failed、needs_input、not_applicable、blocked、cancelled、needs_reconcile。首版缺输入在预览排除/阻塞，或作为该步骤结果记录，不实现运行中无限等待人工填写；有其它成功项时汇总为 partial，全无可执行项时拒绝启动。
- 取消请求成功不等于已停止。确认 Adapter 停止且自有子进程退出后才记 cancelled；不支持步骤内取消时显示“等待当前安全边界”，不得伪装已取消。
- 终态不可被迟到取消或旧进度覆盖。取消后保留已有成功项及实际发布结果，摘要区分部分完成与剩余取消；未知副作用优先 needs_reconcile，不以 cancelled 掩盖。合法核对结论通过新事件推进，不改写原始尝试记录。
- 重启后先核对 worker 归属和既有输出；未确认存活或写入状态的 run 进入 interrupted/needs_reconcile，不自动重放写操作。不能仅凭 PID 或心跳超时抢锁。
- 重试建立关联的新 run，重新预览和校验；成功项默认不重做，未知项先核对。首版不提供把取消叫“暂停”、一键续跑或跨文件 exactly-once 承诺。

## 八 执行和安全契约

1. DB 先持久化 run 接纳及逐步意图，再开始外部副作用。请求幂等绑定、plan 消费和 queued run 创建在同一任务库事务提交；注册/容量等检查失败不消费计划。接纳以 client_request_id 和请求摘要去重；提交成功但响应丢失时查询同一 run，不重复创建。
2. 预览冻结源、依赖、目标、模板/配置及 action 版本。执行前比较指纹及原值；后续步骤只能继承本次已验证回执引起的已知变化，不能重新采样吞入外部修改。新增效果/范围或无法证明的变化需重新预览确认。
3. Adapter 声明实际读写文件、目录重叠、DB 与 Native 资源，统一 Coordinator 按固定规则获取资源，避免嵌套旧队列死锁。owner/token 保持到自有子进程 close 和发布清理完成，副作用及发布前复核所有权；归属不明不强行解锁。原生子进程以本任务配置和身份运行，只终止自有进程；不附着用户正在编辑的 FreeCAD 执行批量写入。
4. 写 CAD 前要求保存并关闭本批目标文档；逐文件备份/CAS、暂存发布、失败保留原件及最终重开保持领域规则。缩略图重生不得为了省事改用户 GUI 的持久偏好。
5. 普通改名既有“不自动备份、不新增确认弹窗”约定不能被统一框架偷偷改回。预览明示 Adapter 的确认/备份策略，统一运行摘要不再叠加重复确认。
6. 取消、失败、部分发布、回滚不确定和人工待确认分别记录。一个文件/步骤失败不掩盖其它结果，已发布输出不能从回执中消失。
7. 成功后由 Adapter 指定局部缓存/索引更新及整批收尾，不逐文件全量重扫；树刷新只由已确认实际变化触发。
8. 全部路径、对象引用和 action 参数校验工作空间权限及授权根；沿用 Host 本机访问边界，不增加无鉴权远程执行入口。实际工程路径、日志、DB、截图及映射只留本地，不进入公开样例或发行包。

完整 T1c/T2 还须按动作冻结全部实际依赖 SHA、内部节点/实例及材料/模板配置，绑定 owned PID+nonce 与 actual close，由同一 Coordinator 协调。V2 effects 不变；V3 单文件试点不授予业务缓存、CAD 或输出写入权。扩展写效果前须补领域 CAS、artifact 和 `needs_reconcile` 持久契约；发布或缓存已提交而任务回执未知时先核对，不自动重放，也不以 cancelled 掩盖。具体门槛见 [T1c T2 受控执行契约](../cad/CAD后续能力实施规划.md#t1c-t2-受控执行契约)。

## 九 材料 尺寸和重量

这三类是首批业务需求，但分别记录数值、单位、来源、对象身份、算法/材料映射版本、时间及输入指纹。测量结果允许为空并带明确原因，不能将未知质量记成 0 或猜默认材料。

- **材料牌号**：读取 PartMaterial 等已保存属性，保留来源冲突。通用材料赋值服务尚未实现，现有 BOM 批量字段不包含该字段；图纸标题栏有材料文字不代表模型已赋物性。
- **尺寸**：复用当前主实体 XYZ 边界盒算法，明确坐标系和放置/缩放条件，不显示 PNG 像素尺寸，不把轴对齐边界盒当最小包围盒或毛坯尺寸。直径 × 高度属于后续识别能力。
- **体积与密度**：只对明确有效的最终实体计算，不能把 Body、Tip、BaseFeature 和历史特征重复相加。密度须来自实际物性材料或用户明确配置的版本化映射，不凭牌号字符串悄悄套常数。
- **重量显示**：产品可称重量，数据按质量 kg 记录，不与力 N 混用。采用单位化计算；若体积为 mm³、密度为 kg/m³，质量 kg 为 `volume_mm3 × density_kg_m3 / 10^9`。数据缺失时标记 needs_input，不把读取任务伪报为质量已获取。
- **总成**：后续按真实实例及数量汇总，处理缩放与重复引用；有任一未知质量时明确不完整，不能把唯一文件集合直接相加当整机重量。
- **Rigid 修正**：先报告宿主、实例、保存的刚柔性及明确失联端；真正同步须专项保留对象身份、Joint 两端子路径、组归属和位姿，并在副本保存重开验证后才能注册可写能力，不删 Joint、不自动翻转 Rigid。

上游接口依据：[TopoShape API](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/TopoShape_API.md) 区分 BoundBox 与实体 Volume；[Quantity](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Quantity.md) 提供带单位计算。Rigid 变更可能影响接地、放置与父装配关节，参见 [AssemblyLink 源码](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/Assembly/App/AssemblyLink.cpp)。这些 API 能力不替代本机质量或装配更新的专项验收。

## 十 API 和未来脚本

拟定独立 `/api/batch-tasks` 管理契约：action catalog、任务 CRUD/版本校验、preview、确认接纳 run、按请求 id 查询、run 明细/事件游标、cancel、reconcile、retry 和归档。每个请求显式绑定工作空间；未知版本、重复但摘要不同的请求和过期计划拒绝。

未来导出为版本化任务 JSON 加调用受控 CLI 的薄脚本。JSON 是任务定义，不是可长期复用的执行许可；CLI 与网页复用同一 validate/plan/service/runner，默认 dry-run，真正执行重新核对范围、输入/目标指纹和确认摘要。

- Web 与 CLI 优先连接同一个本机 Coordinator，不能让脚本绕过正在运行的 GUI/Host 锁。独立离线执行待跨进程资源协调及恢复验收后开放。
- action 显式声明是否需要 FreeCAD GUI/桌面环境；能由 CLI 发起不等于可以无显示环境运行。环境不满足时预检拒绝，不静默换算法。
- 脚本使用固定入口和参数数组，不拼接用户路径为 shell，不接受 DB 中任意命令/eval。平台包装可有差异，业务算法只有一套。
- 本地可运行导出可能包含私有路径/参数，需提示隐私；可分享模板默认去掉工程输入、绝对路径、凭据及运行日志，用根目录别名和待填参数，不能宣称自动完整脱敏。
- 返回确定的 run id、汇总和退出码，保留部分成功、取消、待核对及需要输入的区别；不能只有一个成功布尔值。

## 十一 分期实施任务

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| M0 契约冻结 | 本任务书评审、存储/备份决定、MVC 模型、状态机、Adapter/资源契约及迁移清单 | 明确 schema/备份 owner，验证普通改名与 CAD 写入策略不被统一抹平；不迁移生产数据 |
| M1 通用管理骨架 | 任务 DB、购物车、多个定义、preview/run/历史、Primary 监控；先接独立合成动作及普通文件只读动作 | 刷新/关闭/重启查历史；取消失败不伪完成；能注册非 CAD action 而不改核心或页面分支 |
| M2 CAD 只读及缓存 | 属性/材料字符串、显式目标边界盒、已有缩略图缓存、链接与 Rigid/Joint 报告 | 严格所选范围、对象/实例身份、逐项缺失原因、缓存来源及取消能力；不依赖先全量图册更新 |
| M3 受控写入试点 | 先迁已验图纸精确修正/新稿；再接元数据/标签、缩略图重生及链接路径修正 | 先一个 Adapter 完整通过备份/CAS/取消/崩溃窗口/部分发布/重开，再逐个扩大，不同时重写所有算法 |
| M4 物性及装配专项 | 体积/密度/质量只读计算优先；材料写 CAD 与装配更新分别评审 | 单位、实体/实例、未知值和真实几何对照通过；装配安全门槛不因任务平台完成而降低 |
| M5 CLI 和脚本导出 | 通用 JSON 导入导出、同源 CLI、受控脚本、机器可读回执 | Web/CLI 同计划同结果；跨进程锁、取消、恢复、权限及隐私验收，旧计划不可重放 |

M1 后可让新批量需求接入统一管理；旧入口按 Adapter 成熟度逐步增加“加入批次/查看任务”，再切换执行权。单个任务只由一套调度器拥有，不能新旧队列同时启动。未接入工具保持原流程，不设置“全部迁完才能使用”的大迁移门槛。

## 十二 验收清单

- Model/编排：依赖排序稳定；循环/缺前置拒绝；逐文件与整批 scope 不重跑；不适用/缺输入与失败分开。
- DB/恢复：定义 revision 冲突、冻结快照不漂移、事件序号、分页/归档、迁移失败保留、备份恢复及输入隐私；重启未知写入不得自动重放。
- 幂等/并发：双击、响应丢失、同请求不同摘要、多页面/多个 CLI、目录重叠、同模型多实例和资源租约均有独立测试。
- 取消/失败：排队取消、运行中取消、取消 HTTP 失败、worker 不支持中断、子进程未退出、部分发布和回执落库失败；独立安全项继续。
- GUI：浮窗和 Primary 同步、关闭呈现不取消、快速完成不闪动、错误不自动藏起、减弱动画、跨 View/工作空间迟到响应；计数区分零件/实例/文件/action。
- 文件/CAD：外部修改拒绝、合法前序变化才推进指纹、目标冲突不覆盖、备份吻合；未授权源模型及依赖保持不变，明确授权的目标只发生预览列明变化并核对最终回执。图纸维护/出图另行要求源 3D 不写；实际输出与最终独立重开分别验证。
- 物性：独立简单实体、已知体积与明确密度验证单位换算；缺密度、无效实体、混合材料、重复历史节点/实例、缩放及总成不完整不得伪报完整质量。
- 扩展：独立构造至少一个非 CAD action，证明通用层不 import CAD；脚本和网页复用同一服务，未授权 action/代码不执行。

公共夹具独立构造，不复制个人工程。真实工程验收仅在用户授权的本地副本进行，详细路径/日志留仓库外。第一阶段只初始化自己的任务库，不迁移旧业务库或操作生产 CAD；提交与发布另行决定，只包含本任务文件。
