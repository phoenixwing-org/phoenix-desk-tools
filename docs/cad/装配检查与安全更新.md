# 装配检查与安全更新

状态：draft

Owner：Desk Tools maintainers

适用范围：总成详情 Primary 装配工具；当前宿主，不自动递归改写上级或下级

最后核验：2026-11-06

## 目标与当前能力

子装配增删零件后，父总成可能仍保留旧副本。总成详情新增「装配工具」Block，通过一个对话框集中检查并提供后续定向更新，不要求用户逐个往返切换 Rigid。

保存态检查读取明确选中的 FCStd，显示子装配实例的刚柔性、明确相对路径是否存在，以及已保存 Joint 的空连接端或缺失本地对象。检查不依赖索引，不扫描目录、不读取目标文件内容、不启动 FreeCAD，也不修改数据库或 CAD。

Rigid 是设计意图，不是同步状态。路径存在和没有窄范围 Joint 问题都不能证明装配已同步；保存态检查保留 `synchronization: not_checked`。更新是单独的冻结预览与确认发布流程，不能凭检查结果直接保存，也不用普通重算或切换 Rigid 冒充修正成功。

## 详情页与 Primary

总成详情的 Primary「装配工具」提供「检查 / 更新装配」「查看引用」，详情 Header 提供同一工具入口。普通零件、只读图纸不展示装配更新入口。

点击工具后读取当前磁盘文件。对话框 Header 右侧集中放检查、生成更新预览、发布和关闭操作；实例需要明确勾选，不默认全部执行。默认发布验证副本，只有另行确认已保存相关文档并退出 FreeCAD、发布期间不重新打开时才允许尝试写回原文件；当前磁盘模式检测到任何 FreeCAD 进程都会阻止写回，Tools 内存入口另行验收。实际增删、关节与位姿保持数量、预览有效期放在同一窗口，不要求到不同页面寻找下一步。

明确缺失路径和失联端在表内定位，并写入 Bottom 运行日志；范围提示和未知状态用中性文字，不把柔性或无法判定显示成错误。关闭、切换文件或工作空间会取消只读请求、尝试取消已知未发布的自有预览并丢弃迟到界面结果；取消回执未知时不能保证已停止，更不能把正在发布或结果未知的任务改称「已取消、未写入」。

更新记录位于当前工作空间的 `.phoenix/assembly-maintenance/`，包含打开前基线、私有镜像及逐阶段回执，可能含私人路径或结构，不进入提交或发布包。服务重启不恢复旧预览的写入权限；历史查询和结果核对始终只读。

历史入口在正常会话、关闭重开和浏览器重载后都可使用。有限历史明确显示截断，不声称完整或最新；没有列出的记录可使用完整任务 UUID 核对。核对当前工作空间的记录不会恢复旧 job、发布按钮或写入权限。没有开始回执且不知道编号时，可从工作空间本地记录目录核对对应的 operation.json；不通过重复提交试探结果。

## 定向更新的原生边界

定向更新对明确的子装配实例调用 `recompute(False)`，进入 `AssemblyLink.execute → updateContents`。三层独立样件证明：只更新顶层实例不足以传播下层增删，需要按文件依赖与实例层级从下到上更新；不是对整个装配图强制重算。官方实现见 [DocumentObject Python 接口](https://github.com/FreeCAD/FreeCAD/blob/main/src/App/DocumentObjectPyImp.cpp)、[文档重算](https://github.com/FreeCAD/FreeCAD/blob/main/src/App/Document.cpp) 和 [AssemblyLink](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/Assembly/App/AssemblyLink.cpp)。

`updateContents` 会同步副本，部分路径可能删除或重建 Joint/JointGroup；`onDocumentRestored` 在打开文档时也可能调用它。因此基线必须从打开前的保存内容取得，不能等打开后才记录原态，更不能仅凭脚本没有显式删除就声称关节保持。

受控执行流程：

1. 用户明确选择当前宿主中的实例，冻结对象身份、源及完整依赖指纹、全部保存属性和允许变化。闭包上限为 100 个文件、压缩字节合计 64 MiB、Document.xml 合计 32 MiB、全部解压成员合计 256 MiB；外链断开、范围不完整、未知序列化或现有失联端转人工。源零件已经删除时，只有能证明属于所选 AssemblyLink 派生副本、当前源 Group 已无该对象且无其他引用的旧 App::Link，才允许进入删除候选；不是解除缺失目标保护。
2. 在独立自有 FreeCAD 进程及私有配置中关闭自动求解，使用既有持久 Native 门禁、PID/nonce 与实际子进程退出回执。不得附着用户当前 GUI 或覆盖打开且状态不明的源文件。
3. 在私有完整镜像内保留原相对目录与文件名，只保存镜像宿主，不保存依赖。打开后的内存序列化与打开前 XML 对照，覆盖 `onDocumentRestored` 的自动变化；预览实际新增/移除的派生副本。所有存续对象身份、Rigid、局部及世界位姿和用户属性保持，全部 Joint 的组归属、两端对象与完整子路径、实际连接 Frame 不得改变。Detached 的保存 Frame 不强制等于计算 Frame，但两者各自保持；非 Detached 另验保存与实际连接坐标系一致。
4. 暂存保存后，保留可确认的 GUI 及缩略图成员，用另一自有进程直接打开最终宿主核验；不得先显式刷新依赖来掩盖普通重开错误。任何 Joint 丢失、引用变化、依赖源字节变化或被观察到的求解调用均阻止发布。Python 求解入口和可观察 C 调用受监控；内部自动求解另由私有配置关闭，不宣称完整观测所有 C++ 内部调用。
5. 用户确认实际差异后，在十分钟内重新核对源及依赖指纹，持久备份并发布单宿主。默认副本不移动源件，不覆盖目标；写回原件需用户双确认与当前 macOS 主机的 FreeCAD 进程快照。快照不是通用文件锁，不承诺发现所有改名进程或阻止其他程序随后打开。发布使用原件认领、指纹复核和不覆盖安装；未知结果保留备份与证据，不自动重放，不宣称跨文件原子事务。
6. 成功后统一刷新详情、装配树、引用和缩略图/尺寸缓存状态。局部引用刷新不代替完整递归 BOM 索引重建。

引用子页若已打开，发布事件会使真实引用表重新读取已刷新的投影，不只更新计数或删缓存；该次读取不再触发磁盘刷新或索引重建。晚到的旧请求不能覆盖新行数据，也不能跨工作空间覆盖结果。

本操作保留原有显示属性和内嵌缩略图，不重新渲染图片。发布后图册行标为过期，尺寸缓存失效；需要新图片时使用重新生成缩略图操作，不能把保留下来的旧图视为更新后几何截图。

未产生实际增删差异时只报告「无差异」，不发布，也不据此宣称问题已修复。验证失败、取消、过期或源件变化后，旧预览不能继续发布。输出已经发布而索引刷新失败时，结果仍明确标为已发布，另列刷新提示。

HTTP 只接受工作空间、当前文件、所选实例或任务 UUID，以及发布模式和双确认。Native 脚本、引擎路径、源指纹、暂存路径和安全回执均由服务端构造；请求不能注入。历史只查询固定目录中的有限条目，不搜索工程或恢复执行权限。

打开前仅允许已审阅的空 JSON Joint/GroundedJoint Proxy、对应 Joint 上的空 Suppressible 扩展，以及空表达式引擎。未知 Python 类型、扩展、替代载荷和非空表达式均转人工处理；这不是通用的安全 CAD 脚本执行器。实际 Frame 核验针对冻结文件的当前几何与保存连接值，不能证明未归档的外部零件旧版本几何从未变化。

当前原生适配器仅放行已验 FreeCAD 1.1.0 的指定构建提交；升级或不同构建在补验前转人工处理，不沿用旧版本的求解与序列化结论。

已打开文档的内存更新应另走 FreeCAD Tools 的原生事务与撤销，不和磁盘写入混用，也不自动保存。需要新的受控动作契约，不扩大现有批量任务 V2 的只读白名单。

### 本轮收口与人工点检

沿用现有装配工具目标，不重复开发已经接通的入口或另开自动修正通道。先完成当前宿主的小闭环，再考虑零件升级、移动目录和批量接入。

1. 自动回归保存态检查、预览/发布生命周期、历史只读核对、已挂载引用表刷新和页面上下文隔离；Registry 与 LOCAL 两种 Wing 真源分别验证。
2. 人工只使用独立构造的样件工作空间，进入总成详情的 Primary「装配工具」。核对普通零件/独立图纸不出现更新入口、未选择实例时不能生成预览，以及长表格、窄屏下 Header 操作仍可找到。
3. 生成预览后核对新增/移除清单，先生成默认验证副本。确认原宿主与依赖未改写；发布后详情、装配树和已打开引用页刷新。旧内嵌图片不应冒充新截图，图册/尺寸缓存应标记过期。
4. 检查关闭、切换文件和重新打开：未发布预览只能取消自有任务；已发布、发布中或结果未知时不得重复发布。历史与按 UUID 核对始终不能恢复写入权限。明确 Joint 问题应在 Bottom 日志定位，无法判断的状态不显示为修复成功。
5. 原件写回成功路径另验：需先保存并退出用户 FreeCAD，再对独立样件运行现有生产流程脚本；仍使用真实进程占用检查，不以假快照、关闭用户进程或改门禁绕过。该前提未满足时，只记录阻断，不把目标标为完成。

测试只使用独立构造的 ZIP/XML 与原生样件。私人文件、绝对路径、截图和几何不进入仓库、CI 或发布包。后续 MCP worker 客户端已补齐，原缺依赖的类型检查阻断已解除；这不替代本功能尚缺的原件写回与人工界面验收。
