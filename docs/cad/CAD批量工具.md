## 入口与 View

「工具」Ribbon 将不常用 CAD 批处理收敛为一个「批量工具」入口。入口页及所属工具的左侧 Primary 共享「功能」Block，由 Workbench 在右侧主编辑区打开/激活独立 View。不嵌套第二套 Tab、不自建 Portal、不复制现有工具实现。旧页面地址继续兼容，各 View 保留自己的参数和结果。

「功能」为 Primary 第一个内容 Block，位于页面上下文及状态摘要之前。按钮等宽等行高，按面板实际宽度自适应列数：窄栏单列，拉宽后多列；长标题允许换行，保留键盘访问顺序、当前页禁用与 Wing/Element Plus 主题。其他页面的操作区默认布局不变。

| 功能 | 页面标识 | 本轮范围 |
| --- | --- | --- |
| CAD 批量工具 | `cad_batch_tools` | 导航与说明，不执行写入 |
| 错误修正 | `xlink_fix` | 原链接修正扩展：链接路径、属性计数可单独或一起分析 |
| STEP → FCStd | `step_batch` | 复用现有 FreeCADCmd View/API，不改变转换规则 |
| SolidWorks → STEP | `sw_step_export` | 复用现有 View/API，仍需 Windows / SolidWorks COM |
| 编号查重 | `part_dedup` | 复用现有 View/API，不自动删除或改名 |
| 批量属性写入 | `batch_attributes` | 一文件一行预览目标/字段/来源，勾选文件后确认写入可写字段 |
| 名称统一 | `name_normalize` | 属性与改名分别预览、确认，逐文件复用单文件改名 |
| 关联文档同步 | `document_sync` | 勾选改名记录、整理最终规则，转入独立批量改名 |
| 总成链接标签修正 | `assembly_labels` | 一 ASSY 一行预览待修正数量，勾选后逐总成应用 |

## 共用搜索目录

「关联文档同步」只提供历史规则；旧目录选项随规则交接到独立「批量改名」任务。多目录、文件名/文件内容预览和文件夹改名统一在批量改名中处理，不自动使用 CAD 共用目录。

入口页及所属批量工具的 Primary 共用「搜索目录」：

- 点击输入框可选工作空间的一级目录；也可直接输入更深的相对目录，或用文件夹按钮选择。`.` 明确代表根目录，空值不会被解释成全工作空间。
- 进入 View 不自动探测目录或扫描文件；点击目录输入框或「刷新」时才浅层读取一级目录元数据，不递归扫描业务文件、不初始化索引。文件夹选择只改变搜索范围，不切换工作空间。
- 「选目录」从左侧当前有效目录打开；输入无效时回退当前工作空间。Web 原生选择端点接受 `path_hint`，路径作为参数/环境传递，不拼入脚本。取消不更改选择。
- 选择由 Pinia 共用，并按工作空间写入本地偏好；切换工具、关闭重开 View 或整页刷新均恢复上次目录。只保存目录字符串，不保存预览、勾选、执行锁或写入任务；空目录也原样恢复，避免意外扩大到根目录。同源窗口新加载时读取最新保存值，已打开窗口不强制同步正在使用的范围。
- STEP / SolidWorks 只共享来源目录，输出目录、递归选项等仍各自保留。旧工具偏好仍可保存，但旧目录回包不覆盖本次共享选择。
- 执行前验证目录存在且位于当前工作空间内；拒绝 `..`、符号链接和越界目录。取消原生选择不改范围，过期工作空间与晚到响应不接纳。
- 范围变化立即清除旧分析/预览与属性写入勾选。工具正在分析、执行或确认写入时暂时锁定目录，防止从另一个 View 改变执行范围。

Main 使用 Wing `PnwPageLayout`，Primary 使用 `PnwPrimaryPanel` / `PnwPrimarySection`；顶层标题行与分隔线共用框架高度，不为单页添加对齐偏移。Desk 只持有范围缓存、工具参数与业务执行流程，不复制 Wing 的 Header / Section 结构。

## 错误修正：分析与写回

1. 在 Primary 设置工作空间内修正目录，勾选检查项（默认链接、属性都选），点击「分析」。结果按类别分组，某类失败不被另一类成功掩盖。
2. 链接组保留候选/手选流程；属性组按文件显示对象名、声明计数和实际计数，允许取消勾选文件。
3. 「执行修正」确认链接处数与属性文件数，提醒关闭 FreeCAD 中相关文档，避免旧内存随后覆盖磁盘。
4. 先执行已确认的属性计划，再执行链接修正，避免自身链接写入令属性哈希失效。各类独立反馈；没有跨文件全有或全无事务，不把部分成功显示为全部完成。

属性检查扫描目录及子目录中的 FCStd，不依赖索引；链接仍使用现有 CAD 索引，兼容独立 Document.xml 模式。独立 XML 模式不能同时做 FCStd 属性检查，UI 应明确要求切回目录模式。

### 属性计数边界

- 检查对象直接 Properties 容器的 Count 缺失/不匹配，只计直接子 Property，忽略注释/CDATA/嵌套业务内容。
- 只改 Count，不改业务值、Label、分组/显示元数据、XLink、形状或 GUI 数据，不从文件名推断写入值。
- 与文件详情写入复用同一计数算法；文件详情按表单写字段，批量修复仅改结构。
- 不建立/刷新 CAD 索引或写偏好；符号链接跳过，路径不能逃逸工作空间；坏 ZIP/XML 显式报错，不宣称整个目录通过。
- 上限：1000 个 FCStd / 20000 目录项；单 ZIP 64 MiB、Document.xml 16 MiB、总解压 256 MiB。超限需缩小范围，不默默截断。
- 计划绑定工作空间与 SHA-256，10 分钟有效。换范围丢弃前端结果；文件变化、计划过期/API 重启需重新分析。只写本次分析的选中文件，单文件原子替换、失败保留原件。

## 批量属性写入

来源对象豁免覆盖 `Part::Feature` 与 `Part::FeaturePython`：必须由所选 Body 或其拥有的 `PartDesign::FeatureBase` 通过 `BaseFeature` 明确引用，且来源没有独立 BOM 属性。容器仍由单文件相同的 Wing 根选择决定；不根据图标、对象名称或隐藏状态豁免，不删除来源节点。没有实际来源关系或已有独立属性的多个对象继续阻止批量写入。

独立 View，不混入错误修正的默认动作：选择目录 → 预览对象/字段 → 单行或勾选文件 → 确认写入。沿用 Wing 根 Body/Part 选择；批量歧义检查将已选根的类型临时排除后再次询问 Wing，保持 Group 关系，不复制根选择规则。不把引用节点当新的 BOM 真源。「包含图纸」默认关闭：有图纸后缀的不解压，其他文件识别到 TechDraw 后也不列入结果；开启后只显示跳过原因，始终不能写图纸 BOM 属性。改变选项须重新预览。

一文件一行、一个勾选框，五个属性各占一列：PartNumber、PartVersion、TypeCode、ModelSeries、PartName。值相同只显示一次，不同才显示当前/目标两行。黄色底色仅表示可写差异，不逐字段重复“待写入”；来源/原因通过字段提示保留，不可写原因同时显示在单元格中。默认只补缺失/空值；覆盖已有值须先开启选项、重新预览，并再次确认。默认零勾选，勾选文件只选择后端判定 eligible 的字段，“勾选当前可写项”只选择当前可见文件；前端不再单独勾字段，API 仍验证字段白名单。

Header center 放文件名/相对路径搜索与「全部｜待写入｜问题」三个分段标签，仅在前端过滤现有预览，不触发扫描、读取或写入。待写入只包含仍有可写字段的行，不含一致、已写入或正在写入的行；问题包含需确认、失败、结果未知，以及虽然部分可写但仍有字段冲突/保护的行。部分可写且有冲突的文件可以同时出现在待写入/问题中，勾选只写可写字段。跳过/读取错误也合并进同一表格，显示黄色需确认及原因，禁止勾选写入，不再散列在表格下方。筛选不改变勾选；隐藏的已勾选文件会在页面和写入确认中提示数量，可「显示全部核对」或「取消全部勾选」。

名称推荐与文件详情、名称统一共用规则：已有主对象 `PartName` 优先；未设定或为空时，使用「名称补全来源」选择的标签名（默认）或文件名。空标签回退文件名，索引投影不能冒充已有 PartName。改选来源会清空预览与勾选，必须重新预览；允许覆盖选项也不能让文件名覆盖已有名称正文。

名称有效性在去掉编号/版本及装配后缀后检查：空白或仅一个英文字母（不区分大小写，也识别全角字母）不能成为推荐值。已有这类异常 PartName 时标为需确认，不自动改名，也不静默换用标签或文件名；原值保留，用户可在明确的覆盖确认下手工填写正常名称。PartName 未填写时仍可从有效标签名/文件名补全，但提取结果同样要通过检查。`S型支架`、`M6螺栓`、`轴` 等正常名称不受影响。

单文件手工编辑允许明确清空属性；这与自动推荐、批量改名的名称有效性检查分开。读取时区分“属性不存在”和“属性存在但为空”：后者不再被文件名、索引或旧字段别名补回。推荐只在用户主动点击时产生草稿，不因保存空值自动触发。

名称来源切换、图纸选项、扫描/选择数量与勾选按钮合为顶部一行；详细说明分行放 Primary 最后。可写的目标零件名使用文本框，用户可手工修订；已有值受默认覆盖保护，须先开启覆盖并重新预览才可编辑。手工值只允许非空且不是单个英文字母的纯名称，最多 255 UTF-8 字节，拒绝不安全字符及末尾 `.ASSY` / `.Drawing` / `.FCStd`，前后端均校验。非法草稿锁住整行，不能悄悄只写其他字段。

预览快照与未应用名称草稿按工作空间、目录、来源、覆盖及图纸选项保存在本机浏览器，刷新后保留；不写入 Git、CAD 文件或后端偏好。缓存不是执行授权，恢复时不恢复计划 ID、勾选或成功状态，必须重新预览校验磁盘；实际属性已有值或类型变化时继续服从后端保护。缓存不可用时提示用户保留输入内容。状态格中的「写入」独立确认当前行全部可写字段，不依赖其他勾选；成功或失败后该行锁定，其他行草稿、勾选和计划仍可继续。

PartName 只保留纯名称，不含末尾 `.ASSY`，即使旧磁盘文件名未带装配标记也一样。规范化仍复用 Wing 后缀函数，批量属性写入的默认覆盖保护仍生效。单文件详情推荐装配 Label 保留一个 `.ASSY`，文件名保留一个 `.ASSY.FCStd`。批量属性工具本身仍不写 Label 或改文件名。具体提取规则见下节。

每个文件只有一列「状态」，状态枚举属于 Desk 批处理业务，不放入 Wing：

| 枚举 | 显示 | 判定 |
| --- | --- | --- |
| `pending` | 待写入（N项） | N 为可写字段数，不含冲突/被保护字段 |
| `unchanged` | 一致 | 所有字段已一致，无需写入，不表示本次写过 |
| `needs_review` | 需确认 | 无可写字段且存在来源、类型、覆盖或缺少拟写值问题 |
| `writing` | 写入中（N项） | 本次提交的文件，等待后台结果 |
| `written` | 已写入（N项） | 后台明确返回该文件 written |
| `failed` | 写入失败 | 后台明确返回该文件 failed，显示原因 |
| `not_selected` | 未写入 | 本次未勾选的可写文件，不误报成功 |
| `unknown` | 结果待确认 | 已提交但未收到该文件结果，例如网络中断，须重新预览核对 |

写入结束后保留只读的写前预览及逐文件结果，取消已处理行的待写黄色，不伪装成写后重新读取。批量提交消费整份计划；逐行提交在 I/O 前只消费该文件，其余文件仍可使用，失败或断连不能自动重放该行。重新预览清除执行结果并重查磁盘；切换范围不会串用草稿。单个字段可写性新增结构化 `reason`，仅补充诊断，不改变既有安全规则；旧服务回包仍兼容。

来源冲突、没有拟写值、已有非字符串属性、多个独立 BOM 根对象不会自动写。字段写入与单文件详情共用 XML writer，保留 CustomDefine 元数据并修正根对象 Count；不改 Label、文件名、XLink、形状与 GUI 数据。不使用上次填写记忆或新增空值清除策略。

扫描目录及子目录，但不沿 XLink 扩展到其他目录；共用计数修复的路径/符号链接/ZIP 限额保护。计划绑定工作空间、SHA-256、10 分钟有效期；API 重启、到期或消费后须重新预览。换目录/工作空间/覆盖选项清除执行授权；执行前文件变化拒绝该文件，单文件原子替换失败回滚，各文件独立反馈。手工覆盖仅允许该计划授权的 PartName，不能顺带修改其他字段或绕过覆盖保护。

写后仅更新已存在索引中本次所选字段及关联引用投影，不清空或规范化未选字段、不建库、不改扫描元数据或人工 PartKey；文件已提交但索引更新失败时，明确提示“文件已写入，索引未更新”，不误报文件未写入。当前全量重新索引入口在 KT Auto CAD；Desk 后续接入共享引擎，不要求 VS Code 同时运行。

## 名称统一

独立图纸详情只保留文件名编辑，隐藏模型 BOM 字段、全部推荐和属性写入入口；解析到唯一且存在的源模型时提供“打开模型”，文件名推荐跟随源模型当前文件名。源模型未找到或不唯一时只提示，不按相似文件名猜测。普通模型内附带 TechDraw 页面不按独立图纸处理，仍可编辑模型属性。后端独立图纸 BOM 写入同样受保护，改名不会写入旧页面残留的属性草稿。

改名后未找到适用的 Label / basename 项属于正常跳过，结果和日志说明原因，不把“零项可修正”误报为失败。独立图纸的 Source 引用不等于装配实例 Label：没有对应实例时跳过标签同步；实际 App::Link 标签及 XLink 路径仍按适用项处理。读取失败、索引冲突、写入失败等真实错误继续保留。

### 关联文档同步

从批量工具、名称统一 Primary 或改名分析打开独立 View。读取单文件和批量 CAD 共用的 `.phoenix/rename-logs.json`；该历史记录磁盘改名，不代表引用修正全部成功。连续路径链 `A → B → C` 合并为历史名称指向最终名称；按完整相对路径追踪，循环、多去向、同名不同去向均阻止自动处理。最终名称受保护，重复预览不递归扩展。

选择记录和 1–12 个目录后搜索预览，首次默认零勾选。复用 Wing Code 字面、区分大小写、最长匹配的一次替换；默认完整文件名，可选不含扩展名。仅修改文件名和检测为 UTF-8/BOM/GBK 的文本内容，保留编码与换行；不改目录名、二进制内容或 FCStd 内部引用。FCStd 磁盘改名仍走 CAD 专用入口。CATPart、CATProduct 等关联模型不可直接改名，需在 CATIA 中维护关联；CATDrawing 勾选后允许仅修改文件名，保留后缀，内部内容及引用不修改。STP/STEP 仅处理文件名，即使勾选“文本内容”也保持内部字节不变，头部路径清理单独规划。不恢复退役 Code 的扫描、索引或任意旧 API。

联合目录、三个匹配选项与记录勾选按当前工作空间保存到本机 Pinia / 浏览器缓存；记录 ID 以重新读取的历史校验。文件勾选只缓存稳定身份（目录、相对路径、目标名称），重新预览后，范围、替换关系及匹配选项一致且仍可应用的项才恢复；新发现文件不自动勾选。缓存不进入工程 Git，不保留预览计划、文本差异或执行结果；旧 Tab 快照不覆盖最新配置，不自动搜索或应用。

三个 Block 的标题右侧提供各自快捷操作，内容区的重要操作仍保留。预览结果按已命中的后缀列出复选项与数量，无后缀单列；同后缀大小写合并。后缀选择按工作空间与各处理目录缓存，新增后缀默认显示并提示“新增”，不代表应用勾选；隐藏后缀立即取消其文件勾选，批量勾选只针对当前可见且安全的项，不再扫描目录来生成后缀列表。

独立「工具 → 批量改名」已提供通用任务流程，见 [独立改名任务边界](../code/Desk-Code功能退役.md#独立改名任务2026-10-06)。现阶段此 CAD 页面保持原流程；下一阶段再把历史链整理成 A→B 列表，连同目录交给独立 View，不重复实现执行器。

沿用 Code 忽略规则，拒绝目录包含/重复、符号链接、硬链接写入和目标碰撞。超过 4 MiB 不替换内容，超过 64 MiB 跳过文件；目录项 20000、命中文件 2000、计划输出 32 MiB 为上限。预览绑定工作空间、范围、选中行与源 SHA-256，30 分钟有效，应用或服务重启后不可重放。实际执行前再次检查目标/源变化，每个选中项保存原件与逐项 JSON 到所选目录 `.phoenix/document-sync-backups`；失败后继续其他独立项，错误激活 Bottom 日志，不宣称跨文件事务。该视图的结果记录与 CAD 改名历史分开，不自动提交 Git 或刷新 CAD 索引。

名称以主对象属性 `PartName` 为准，仅在未设定或为空时按所选「标签名 / 文件名」补全，默认标签名；标签为空才回退文件名。标签与索引不反向覆盖已有 PartName 的名称正文。单文件详情、批量属性写入和名称统一采用同一来源优先级。

- 结构化标签去掉前置零件号、版本；类型码/型号系列前缀只有与已知元数据一致时才去掉，不猜测普通名称的分段。
- PartName 是纯名称，去掉末尾装配标记（大小写、重复 `.ASSY` 均规范化），保留名称内部连字符和内部 `.ASSY` 字样。
- 纯名称为空或仅一个英文字母时禁止推荐及批量改名，预览显示需确认；例如结构化标签末尾只有类型码 `S`，不能将其推荐成零件名。无效项不进入写入或改名计划，不能通过跳过属性写入绕过检查。
- 主对象 Label 已明确带 `.ASSY` 时，旧文件名即使缺少装配后缀，生成的装配标签仍保留一个 `.ASSY`，不因提取纯 PartName 而丢失。
- 独立构造示例：`720422.003-测试框架装配.ASSY` → PartName `测试框架装配`。生成的装配 Label 为 `720422.003-测试框架装配.ASSY`，装配文件名只保留一个 `.ASSY.FCStd`。
- 更改名称补全来源后，旧预览、勾选与改名分析失效，需重新预览；推荐不等于写入。

类型不符、不安全或无法确定的名称阻止批量处理，不以其他来源静默替换。**预览后即可分析改名与引用，不要求先写属性**。属性已一致时，可直接勾选改名；属性有差异时，也可先看引用分析，但执行改名前须确认属性写入并重新分析。属性写入会使旧分析失效，两个写阶段分别确认。

主属性对象仍由 Wing 选择。批量安全检查识别导入 STEP 的 `Part::Feature` → `Body.BaseFeature`（或 Body 内 `FeatureBase.BaseFeature`）依赖：没有独立 BOM 属性的导入源不当作第二个零件，属性仍写到 Body/Part，不写导入源。支持外层 `App::Part` 容器包含多个原始几何节点、其中一个被 Body 使用的情况；只排除关联明确、容器及所有成员均无独立 BOM 属性的纯几何容器。未关联容器、包含独立 Body 的容器或带独立 BOM 属性的源仍需确认，不根据可见性或对象名称猜测。

预览表格中的文件路径可点击进入「文件详情 → 编辑属性」，不改变批量勾选；确认完成改名后链接使用新路径。单文件编辑后需要重新预览，旧计划受指纹校验保护。

跳过属性阶段直接改名时，也会在首次改名前备份源文件；页面「改名源文件与宿主备份位置」可查看恢复依据。引用分析本身不写 CAD 文件、不触发索引更新。

Header 中搜索文件名/源及目标路径，快捷筛选「全部｜正常｜需修正｜需确认」只过滤已有结果；绿色正常、黄色差异/待修正、黄色需确认，执行失败红色。读取异常留在同一表格中；空筛选保留表头。勾选当前只作用可见行，不清掉隐藏选择；执行确认明确列出隐藏选择数。使用说明位于 Primary 最后的 Block。

搜索目录只限定名称处理对象，**引用分析查整个工作空间 CAD 索引**，包括其他目录的直接宿主、间接上层装配。未入索引或工作空间外依赖不能保证覆盖，外部修改后应先更新索引。

引用选项与单文件弹窗共用 Pinia 选择记忆，首次默认勾选路径、标签、basename；更改后改名分析失效。后台任务先检查源文件、索引快照和宿主指纹，备份源文件及要修改的直接宿主，然后逐个调用单文件 `renameBomFcstdFile` 入口：完成一个文件的改名与引用修正后再处理下一个（仅 incoming，不写无关节点）。同一批中的装配也被改名、一个宿主引用多个改名文件、搜索目录外宿主及唯一 basename 引用均纳入处理。没有宿主正常跳过，不调用空宿主写入。来源歧义、目标冲突、缺少文件/符号链接、分析后外部改动会阻止相关文件执行，不阻止后续通过安全检查的文件。引用修正部分失败保留改名记录、宿主错误与备份路径，继续检查下一项，不标“全部完成”；同一宿主在批次内的已完成路径写入会更新指纹基线，不被误判为外部修改。只有全局索引被其他操作改变、改名后状态无法可靠确认等全局安全问题才停止后续项目，未执行项显示具体原因。不同文件没有跨文件原子事务，也不宣称备份能自动还原全工程。

逐项结果独立于表格筛选写入 Bottom 运行日志；失败、引用待修正、未确认和未执行均列出源/目标文件及具体宿主原因，并自动展开 Bottom、激活「运行日志」。请求错误、后台任务异常与索引更新失败同样可见；轮询不重复追加同一结果。普通成功进度不会强制抢占面板。

批次实际改动磁盘后（包括部分失败）统一启动一次全工作空间 CAD 索引更新；只有属性差异、无需改名时在属性阶段完成后启动。不会每改一个文件就全量扫描，引用修正服务所需的局部投影刷新仍保留。页面只轮询该任务，不重复发起更新；索引失败不覆盖文件执行结果，需到 CAD 索引核对/重试。所有备份长期存放在 `.phoenix/name-normalize-backups`。

Primary 显示逐文件实际进度，随后跟踪一次 CAD 索引更新。CAD 索引发现阶段总量未知时显示阶段和已处理数，不编造百分比。客户端轮询断连不重放写操作，服务重启后须核对磁盘/记录，内存任务不自动恢复。

临时工作空间回归覆盖跨目录/间接引用、选中装配先改或后改、basename-only、空宿主、分析后文件变化、标签部分失败、选项关闭、一次索引触发及失败分离；未对用户 CAD 执行写入。用户确认单文件改名正常，但明确尚未通过真实批量 FreeCAD 测试，两者不混记。详见 [点检隐私审查归档](CAD改名与装配标签-点检隐私审查-归档.md)。

## 装配结构：当前宿主的引用标签修正

文件详情优先显示当前 FCStd 的真实 `Group` 层级及节点 `Label`，不以跨文件引用图中源装配的名称替代宿主中的名字。左侧 `#` 是层级定位（`1`、`1.1`…），不会写入文件。缺少可识别对象结构的旧格式回退为引用图；下级源文件只读。

“填入推荐标签”仅生成草稿：按宿主对象、XLink 文件和目标对象定位，沿投影引用读取实际零件节点的显示名。目标缺失、循环、工作空间外或层级归属不唯一时跳过并提示，禁止回退为整份文件的总成名。同一级同一实际零件只有一个实例时不加号，多个按 `Group` 从上到下追加 `.001`、`.002`，不同层级独立计数。重复叶子零件可合并一行，数量为实际实例数，点击数量展开逐实例编辑；带实体下级的子装配分别列出，避免混合各自的子节点。

进入装配结构即使用已加载的规则名进行只读比较：不一致的标签标黄，下方显示推荐名及小“填入”按钮，状态为“待修正”；不自动改输入值、生成草稿或写盘。小按钮只填本实例；顶部按钮填全部。显式填入后显示“待应用”，撤销会恢复差异提示。隐藏实例差异只反映在合并行状态，不增加说明行。

列顺序为 `#｜链接标签｜数量｜状态｜目标文件`。鼠标悬停或键盘焦点进入某行时，在最右侧目标文件区域浮出“撤销”（恢复草稿前原名）、“应用”（只写该实例）、“改链接”，不另占操作列、不换行增加高度；触屏保留可见操作。顶部“应用全部”提交当前总成的待修改项。单行保存后保留其他行草稿；重复点击规则预览不会撤销已有建议。深浅主题的输入框、修改提示、图标及状态均使用主题配色。全部展开、折叠、数量、填入推荐和层级选择合为同一工具行；去除 420px 高度上限，表格填满剩余空间。分行简短说明放 Primary 最后。

目标文件的主文字和点击跳转均指向沿对象引用解析出的最终零件文件；经由的直接总成路径仅显示在 tooltip，不占说明行。用于“改链接”和标签写回的直接 XLink 路径、对象标识保持不变，不因展示最终文件而改写真实引用。

写回校验宿主对象、目标对象、原 Label 与文档指纹；预览后层级或内容发生变化时要求刷新。只修改当前总成相应 `Label`，不改 XLink 路径、内部对象名、几何、被引用源文件；写前备份至 `.phoenix/reference-label-backups/<批次>/<宿主路径>`，写后局部刷新该宿主引用索引。旧的文件级同步遇到同文件多个目标对象时拒绝统一覆盖，转到此界面逐对象确认。代理只对用户真实 CAD 读取预览，写入回归使用临时 FCStd 样本；用户另已确认多个文件逐个应用、FreeCAD 保存重开正常，时间戳提示独立跟踪。
