# 失效链接一键修复：交互与安全规划

状态：draft（问题分析与实施建议，不代表修复入口已交付）

Owner：Desk Tools maintainers

适用范围：Desk 本地 CAD 模块；FreeCAD Tools 作为后续入口与内存执行适配

最后核验：2026-11-03

## 1. 建议结论

在文件详情的「装配结构」header 增加 **检查并修复链接**，引用页提供同一入口。点击只检查，不写入：在一个对话框内集中显示问题、建议目标与原因；用户确认后批量修正明确项。多个候选、找不到目标或升级兼容性不明时，才进入现有「修改 XLink 链接」对话框。

不是给旧批量修正接口直接加按钮。先补齐确定性判定、冻结计划、持久备份和写后核验，避免界面更方便却扩大误修范围。第一期只处理当前宿主，不递归修改整个工作空间，也不做自动升级。

FreeCAD Tools 可增加同名按钮，先作为检查/预览入口；以后支持有撤销的当前文档内存修复。**磁盘修复与内存修复必须分开执行，不能同时改同一文件。**

## 2. 先把不同问题分开

| 问题 | 实际含义 | 建议操作 |
| --- | --- | --- |
| 文件移动、改名，旧路径不存在 | 文件级 XLink 路径断开 | 查找原目标，预览相对路径修正 |
| 旧版删除，只剩其他版本 | 可能需要升级，而非单纯修路径 | 列出同零件号全部版本，明确确认版本变化 |
| 旧版仍存在，但用户想用新版 | 当前链接有效，只是主动换版需求 | 单独「替换/升级」，不当作错误自动处理 |
| 文件存在，但内部目标 Name/子路径不存在 | 对象级或拓扑引用失效 | 人工确认；仅改 file 属性不能解决 |
| 黄行：Link.Label 与标准名不同 | 显示标签差异，不等于断链 | 独立标签预览；自定义标签可保留 |
| 索引/BOM 快照过时 | 展示投影不是最新完整递归结果 | 局部刷新后仍提示需要完整索引 |
| Joint 连接端为空、子装配副本/Rigid 未同步 | 约束或原生装配状态问题 | 独立诊断；不猜接、不删 Joint、不往返切换 Rigid 消警 |

一条引用可以同时具有多种状态，不能只用一个黄色代表全部问题。文件已解析也不代表目标子对象、关节或 BOM 数量已经验证。

2026-11-03 已修正引用页的黄行判定：不再直接按文件级 `link_label != rule_label` 比较，复用装配结构的实际目标对象及同级重复实例编号。只在完整可核对时标记明确差异；无法确认来源、旧序列化、缺目标或不完整层级时保持 unknown 中性状态，不要求用户删掉合法 `.001/.002` 编号。该显示修复没有改写 CAD 或索引。

普通入向、出向及详情查询仅读取数据库投影，标签核对为 unknown；仅显式 `refresh_disk=true` 后在数据库 lease 关闭外核对当前宿主的出向标签，不扩读入向父宿主，也不由发布后的只读刷新触发。

局部刷新仍会使后台完整 BOM 快照变成 stale；它并不证明发生了实际内容变化。引用页对 `partial_refresh` 现采用普通提示，说明如修过链接或调整装配，更新完整索引后再核对 BOM 数量，不再标黄或误述为文件已变化。后台安全的无变化刷新判定另做，不能通过改 ready 隐藏未重建的快照。

中文内部 Name 应保留并被读取器正确识别，不通过重命名节点绕过兼容问题；名称不能被 trim、大小写折叠或 Unicode 规范化后当作同一对象。

## 3. 当前已有与缺口

| 能力 | 已有事实 | 本需求仍需补齐 |
| --- | --- | --- |
| 总成/引用页逐条改链接 | 已有 `XlinkReplaceDialog`；装配树能定位实际宿主，包括下级宿主 | 问题集中预览与批量明确项 |
| 人工候选搜索 | 同零件号跨版本列出，版本可选；本轮取消单候选自动选中 | 候选证据、文件角色和对象兼容提示 |
| 目录链接分析与执行 | 有 `analyzeXlinkFix`、`runXlinkFix`、手动 override | 精确宿主白名单、冻结计划、可靠歧义状态 |
| 局部引用刷新 | 可集中刷新指定宿主并使派生缓存失效 | 所有入口统一通知；不能把局部刷新称完整索引 |
| 标签与关节诊断 | 有标签推荐和窄范围已保存 Joint 空端诊断 | 不与路径修复混写，不宣称完整原生校验 |
| FreeCAD Tools 链接同步 | 现有功能只同步实例 Label | 新增独立修链命令、快照、候选与原生执行器 |

旧自动修正当前有以下限制，必须先整改：

- 同 basename 多候选按路径字符串距离取第一项，不是证明唯一；自动查询仍有数量截断。不能沿用其 `fixable` 作为「唯一安全」结论。
- 执行会重新分析，不绑定用户看到的源、目标、候选集合和索引快照；预览与执行可能变成两份建议。
- 底层按完整旧路径字符串替换，可能同时影响同宿主多个实例；未冻结具体对象/属性，也未验证新目标内部对象及子路径。
- 原子替换使用的短暂备份成功后会删除，不是持久恢复依据；尚无完整写后内容反验。
- 没有可证明覆盖 Desk、其他进程与用户 FreeCAD 会话的统一写锁。只检查文件存在，不足以应对符号链接、打开的脏文档和并发修改。
- 批量首个异常会中止，前面的文件可能已写入但索引尚未刷新；写盘成功后刷新失败也可能只返回一个错误，状态不够清楚。
- 旧 `analyze/dry_run` 还可能保存偏好，不应未经拆分就当作严格只读能力提供给 Tools。

可借鉴现有属性修复的一次性计划、指纹检查，以及总成标签批处理的持久备份、逐文件回执和集中刷新；这些模式不等于已有通用全局写锁。

## 4. 用户流程：一个主对话框，不做多步向导

1. 在总成 header 点击「检查并修复链接」。默认只读当前宿主实际保存的引用；不依赖用户逐行点开。
2. 对话框 header right 提供「重新检查」「修正已确认项」，显示检查范围和问题数。详情、日志与候选证据可折叠，不让主要按钮滚出视野。
3. 表格按实际写入宿主分组，显示实例、问题类型、原路径、建议目标/版本、证据和状态。默认只展开有问题的行；正常项可展开核对。
4. 有充分身份与兼容证据的明确项可集中确认；只有一个弱证据候选时在表内标为「唯一候选，待确认」，允许一次核对多行，不为每行强制弹窗。
5. 歧义、无目标、需换版或目标对象不匹配的行提供「选择目标…」，复用现有 XLink 对话框；选定后返回主表，重新核验，仍须统一确认应用。
6. 执行后原位展示逐文件结果。未解决项保留，用户可再次处理；不重放已完成项。

默认范围是「当前文件的直接外链」。后续再增加显式「包含下级装配」：列出会修改的每个实际宿主和文件数；显示根总成不等于授权改写所有下级文件。递归发现中断、无法读取的子装配或部分索引应明确表示范围不完整。

找不到候选时提供「更新相关索引」「在本工作空间选择文件」，不陷入反复搜索死路。工作空间外文件第一期只报告，不自动遍历或写入；扩大目录范围需要用户明确指定。

## 5. 候选与升级规则

候选搜索和自动判定分开：**可以宽搜，必须严选。** 搜索默认按零件号展示全部版本，不能默认最新，也不能只显示旧版本。只有完整搜索范围内通过磁盘与对象核验的候选，才能参加确定性判定。

证据优先级建议：

1. 已有有效路径：不修，不自动升级。
2. 能核验的旧目标内容指纹/变更记录明确指向现存文件，再检查零件标识、文档角色和目标对象：可作为明确路径恢复。
3. 相同完整 basename、零件号/版本、角色且目标对象匹配，但没有足够旧身份依据：显示「唯一候选，待确认」，不要把文件名当稳定身份。
4. 相同零件号、不同版本：显示升级差异，用户明确选择后单独核对目标对象、子元素及受影响关节。唯一新版也不自动替换。
5. 同名多目录、多副本、候选截断/索引不完整或同版本数据冲突：不取最近目录或第一条，进入人工确认。

`.Drawing.FCStd` 不能只因零件号相同就替换模型/装配。`App::Link`、原生 `Assembly::AssemblyLink`、复杂 Link 数组、XLinkSub 的处理能力必须分别声明；首期只支持已经完成保存重开验收的类型，其他类型只诊断。

文件唯一不等于对象唯一。目标内部 Name、类型、完整子路径必须存在且匹配；不能按相似 Label 重建目标对象、重绑 Joint，或承诺跨版本拓扑自动兼容。

修路径不默认改显示标签。若需要对齐标签，作为单独可见的差异与选项处理，保留实例编号、自定义标签、放置、Rigid、关节和所有未授权属性。

## 6. 计划、记录与执行边界

### 冻结计划

复用工作空间数据库及现有服务分层，先明确 DTO，再决定最小 Schema 迁移；不因为新入口另建一套队列或数据库。计划至少包含：

- 计划 ID、协议/策略版本、工作空间身份、明确宿主集合、范围完整性、候选搜索范围和索引 revision。
- 源文件真实路径与 SHA-256；实际宿主对象 Name、属性名、原始 XLink 完整值及影响实例数。
- 目标真实路径、SHA-256、对象 Name/类型/子路径、文档角色、旧新零件号与版本、判定证据。
- 只读差异、允许修改字段、用户逐项确认、有效期与一次性消费状态。

计划默认短期有效（建议 10 分钟，沿用现有修复计划模式）。执行不能重新分析后悄悄换目标；文件、候选集合、范围或索引关键证据改变就使对应计划失效。

数据库记录检查、用户选择、备份位置、写入前后摘要、逐文件结果和索引状态；不把整份模型、PNG 或私人文档内容存进任务记录。历史记录只供审计，不恢复写入权限；服务重启或结果未知后先核对，不自动重放。

### 磁盘执行

按宿主分组、串行执行，同一宿主的一批已确认补丁一次写入；每个宿主独立提交，不宣称跨文件事务：

1. 取得明确文件写入协调权；再次检查真实路径/父目录、链接、源与目标指纹、原始属性和计划。不能以锁不存在推断用户 FreeCAD 没打开文件。
2. FreeCAD 文档已打开、未保存或状态无法确认时，不后台覆盖该 FCStd。引导使用内存模式，或由用户保存并关闭后重新预览；不替用户关闭、丢弃或保存。
3. 在工作空间受管理的 `.phoenix/` 备份区持久备份并记录恢复依据；备份失败不写。暂存替换文件不是持久备份。
4. 只修改计划绑定的对象/属性；如多个实例共用同一旧路径，必须在确认中明确包含的实例集合。保留内部 Name、源模型、其他 ZIP 成员内容、GUI、约束与放置。
5. 写前再次 CAS 复核并原子替换；写后重读核验授权差异、原目标对象仍可定位、非目标内容保持。只读 XML 反验不能宣称已通过 FreeCAD 重算和保存重开。
6. 每个宿主记录 `written / failed / skipped / needs_review / uncertain`；文件写入与索引刷新状态分开记录。写成功而索引失败不能报成「文件未写」。
7. 仅继续相互独立且仍通过校验的文件；共享依赖、全局索引变化或写入归属不明时停止受影响后续项。不要在未知状态下换计划重试。
8. finally 集中刷新已写宿主引用，统一 `notifyXrefMutation`、装配树和计数失效；完整递归索引如确有必要，整批最多触发一次，不逐文件全扫。

错误原因进入 Bottom 日志并定位问题行；普通成功进度不抢焦点。关闭对话框不等于取消后台写入；取消只阻止未开始项，已写入项保留准确回执。

## 7. FreeCAD Tools 的接入

新增独立「检查/修复外部链接」命令，不把现有「链接同步（Label）」悄悄改为修路径。

第一阶段可以从当前已保存文档定位 Desk 的同一预览，但当前 Tools 仅有打开 Desk 根页面的能力；携带工作空间、文档与 repair intent 的跳转契约仍需新增。跳转只授权查看，不直接申请写入；找不到 Desk 时明确提示，不擅自启动另一实例。基础小工具仍不强依赖 MCP/Desk 服务。

后续独立的 Qt 对话框使用同一问题分类和候选规则，执行器分开：

| 层 | 职责 |
| --- | --- |
| 共享纯核心（优先正式 Wing 能力） | 解析、候选证据、版本/角色规则、确定性判断、计划 DTO；不含 UI/磁盘/FreeCAD 调用 |
| Desk adapter | 索引及文件快照、确认、持久备份、磁盘写入、记录与刷新 |
| Tools adapter | 当前 GUI 内存快照、主线程原生 API、事务、撤销、变换/关节不变量核验；不自动保存 |

Tools 当前没有现成 Wing 运行依赖，Python 也不能直接导入 TypeScript。可优先探索显式可信 Node helper 或已配置的 Desk 服务作为纯候选适配，缺运行时就报告不可用，不复制第二套「猜目标」算法。具体分发方式另验，不作为本次已完成能力。

内存模式可保留用户其他未保存修改，但必须独立冻结当前实例、原始链接、目标、子路径、变换及文档/事务状态；通用 document revision 观察并非完整写保护。断链内存拿不到原始外链信息时，磁盘 XML只能作为标注清楚的历史补充，不能覆盖当前内存真源。应用只使用已确认原生 API 和本次事务，可撤销、不自动保存、不关闭来源或用户文档。

MCP 后续只作为同一 Controller 的版本化受控入口，不用任意脚本接口冒充完成的修链工具。缩略图 worker 明确拒绝外链输入，不能复用它做装配修链执行器。

## 8. 实施顺序与验收

1. **先补底座**：对象级只读诊断、完整候选/歧义判定、冻结计划、备份/CAS/反验及逐宿主回执。拆出严格只读 prepare，不改旧接口的含义来冒充完成。
2. **再接 Desk 小闭环**：当前宿主按钮 → 单一问题对话框 → 明确项集中确认 → 人工兜底 → 统一局部刷新。此时不开放升级自动应用或递归写入。
3. **再扩范围**：显式下级宿主白名单、升级核对、现有批量任务队列与持久历史。CAD 写入动作须有独立效果/权限契约，不放宽 V2 只读动作白名单。
4. **最后接 Tools 内存执行**：命令、Qt 预览、原生事务、撤销与保存重开验收；完成前只提供检查/转交，不宣称能安全修复所有装配。

独立构造的验收至少覆盖：

- 同目录、跨目录和多级移动；根总成移动导致相对路径整体失效。
- 同名多目录、多副本、候选超过旧截断数、索引缺失/部分可用、目录无法读取。
- 相同零件号多版本，旧版仍在、旧版删除；图纸与模型同号，禁止自动混用。
- 文件存在但目标对象改名/删除、子元素失效，不能只改路径后宣称成功。
- 中文/组合 Unicode 内部 Name、重复实例编号和自定义 Label；合法标签差异不阻塞路径解析。
- 预览后源/目标/候选/索引改变；符号链接、硬链接、越界路径、无写权限、备份失败。
- 第一个或中间宿主失败、写盘成功而索引失败、响应丢失、取消、服务重启；不重放成功或未知项。
- FreeCAD 已打开/dirty 文档；Desk 不覆盖。Tools 原生模式保留其他修改，撤销/重做保持实例位置和关节。
- 合法关节、原有失联关节、刚性/柔性子装配；不删 Joint、不自动切换 Rigid。
- 修复后重新检查、真实 FreeCAD 重算、保存重开；无新增坏引用或非目标变化。

仓库测试和文档只使用中性构造样本；真实工程点检证据留在仓库外或已忽略本地目录，不提交项目路径、文件清单、几何、截图或映射。
