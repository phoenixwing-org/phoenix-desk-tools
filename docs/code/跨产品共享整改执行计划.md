# Phoenix Desk Tools：三库共享整改执行计划

> 2026-07-21 UI 边界补充：Code 工具的稳定业务 UI 不再由 Desk 和 VS Code 分别维护。当前权威方案见 [Code 工具三端共用算法与 UI 内核执行计划](Code三端共用算法与UI内核-执行计划.md)：Wing 同时提供 pure core、ViewModel 与 Web Components；VS Code 和 Desk 只做 Host adapter，Desk Web 与 Tauri 运行同一前端。

> 本文仅描述 desk-tools 的迁出和消费工作。公共包接口、版本策略与跨端验收以 `phoenix-wing/docs/三库共享核心整改计划.md` 为准。成员排序算法、锁定段与回归契约以 [phoenix-wing · C++成员排序算法规范](../../../phoenix-wing/docs/C++成员排序算法规范.md) 为准。

> 本文继续负责 Code/CAA 专项。CAD Rust、数据库契约和多 npm 子包的迁移，以 [Wing 共享 CAD 核心迁移计划](../cad/Wing共享CAD核心迁移计划.md) 及 Wing 跨语言总计划为准。

## 目标

将可跨宿主的函数排序和 CAA 核心迁入 `phoenix-wing`；稳定的 Code 业务视图同时迁为 Host-neutral Web Components。本仓库继续拥有 Tauri/Vue 工作台壳、文件系统适配和宿主事务。不得将 Vue、Element Plus、FastAPI、`vscode` 或 Node `fs` 隐式带入共享 core/UI。

## P0：一小时基线整改

- [x] 根许可证为 Apache-2.0，包元数据、README 和许可证附录统一标记权利人“上海锟钛”。
- [x] 对 `reorderCppEngine.ts`、`reorderHeaderEngine.ts`、codec、fixture 与服务封装做依赖清单；权威清单见 Wing 共享整改计划的“排序依赖清单”。
- [ ] 将 `/项目调查` 中本仓库专属的调查合并到 `docs/cad/` 的既有迁移文档，外部项目研究不复制进本仓库。

## P1：函数排序迁出

1. 保持现有 golden fixture 输出不变，将纯解析、锁定区、成员排序、重建和诊断迁入 `phoenix-wing/code-core`。
2. 本仓库的 `reorderMembersService` 仅保留扫描、偏好、编码/文件读写、进度、取消和批处理。
3. 页面继续在 desk-tools 的编辑区/工作台中提供多文件表、diff 与确认；它消费 core 的标准结果，不重新计算排序。
4. desk-tools 和插件共同运行同一组 core fixture，任何输出变化必须伴随版本说明。

## P2：CAA 迁出与保留边界

- 将现有 `catdlg-core` 迁为 Wing 公共包，保持 browser/node 入口和 `io-adapter` 注入。
- desk-tools 保留 Vue3 CAA 画布、属性面板、拖放、多 Tab、撤销/重做和 Tauri 窗口流程。
- 保存前必须由 core 生成 diff、校验 IR 和保护 Wizard marker 外代码。

## KT Codegen 消费落地

- [x] `phoenix-wing` 独占 Param、Reader/Adapter、Table、32 Block、Marker、Analyze 和 Renderer。
- [x] Desk Tools 以 `@phoenix-wing/kt-codegen` 包消费，不复制共享规则，不改 Wing。
- [x] Web 采用左侧 Block + 主 View；Node 仅提供工作空间、编码、指纹和源码快照适配。
- [x] 通用页面贡献 Host 支持 Block 显隐和 `pageId + workbenchTabId` 上下文；取消、dirty/冲突与外部变化行为对齐插件。
- [x] 与 `kt-auto-code` 对齐 Analyze/Apply 分层；Desk 的 Node 宿主已按用户授权开启真实源码 Apply，不把文件系统能力下沉到 Wing。
- [x] 源码 Apply 以计划/源码 fingerprint、范围不重叠、同目录临时文件、原子替换、回读验证和失败回滚 fixture 为门禁；插件与 Desk 继续共享 Wing 的 Marker/Analyze 语义，各自保留宿主写入适配。
- [x] Desk 已升级 Wing 0.4.3，并直接消费 `ktCodegenCanApplyValidRegions`、结构化 `diagnostic.marker` 与 Table `layout="page"`/`collapsible`；缺失/孤立 END 只隔离损坏区，完整 Region 仍可安全局部 Apply。

## 完成标准

- 一条排序/CAA 规则修复只修改 Wing core 一处。
- desk-tools 的现有界面能力不因抽包倒退。
- Python 遗留排序入口不再是生产运行时依赖。
