# Phoenix Desk Tools 产品功能归属矩阵

状态：current

Owner：Desk Tools maintainers

适用版本：0.3.x

最后核验：2026-07-23

本文由 Desk Tools 维护，记录本产品每项能力应共享到 Phoenix Wing 的层级，以及必须留在 Desk Host 的责任。KT Auto Code / KT Auto CAD 维护自己的[对应矩阵](../../kt-auto-code/docs/产品功能归属矩阵.md)；两张表使用相同的 `featureId` 对齐，但不互相复制状态。

Wing 已实际导出的能力只认 [Wing 共享能力目录](../../phoenix-wing/docs/共享能力目录.md)中的 `capabilityId`、export 和源码相对路径。跨库盘点过程与阶段决策归档在 [Phoenix AI Workspaces](../../phoenix-ai-workspaces/wing-projects/work/三库功能归属与迁移协调-2026-07-22.md)。本文只裁定 Desk 的产品归属和协同顺序，不替 Wing 或 Auto Code 宣布完成状态。

## 维护规则

- 两张产品表出现相同 `featureId`，表示需要核对行为、契约或 UI；只出现在一张表中，默认是产品专有能力。
- `共享完成` 只用于 Desk 已实际消费 Wing 发布入口的能力；只有代码已在 Wing、Desk 尚未接入时仍标为 `部分共享`。
- `Wing UI` 只接收两个产品已经实际使用且交互相同的稳定业务组件。Workbench、路由、原生面板和宿主生命周期不得为了形式统一而迁入 Wing。
- 新增跨产品能力时，先同时核对两张矩阵，再按“Wing 契约/core → 各 Host adapter → 共用 UI → 删除重复实现”推进。
- 协同优先级：`P0` 当前收口；`P1` 已有双端重复，紧接处理；`P2` 先共享契约或等待第二个真实消费者；`—` 产品/宿主专有，不做对端追平。

## 变更流程

1. 在本表找到 `featureId`，再打开 Auto 对应矩阵检查同名行。
2. 若是 `P0/P1`，在改代码前写清 Wing 目标包、行为真源、双方 Host adapter 和删除对象。
3. Wing 先发布/提供受控本地入口；两个消费仓库继续锁 Registry 精确版本，本地联调只用既有 resolver。
4. 两端消费并通过共同 fixture 后，才把状态改成 `共享完成`，随后删除兼容 facade 或重复业务 UI。
5. 如果只需要宿主原生能力或没有第二消费者，把功能保持为专有，不创建空的共享抽象。
