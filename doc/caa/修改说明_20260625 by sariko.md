1. CAA 路由与页面定位
- 问题：`/?page=caa_dialog_home` 是入口页，真正编辑页是 `caa_dialog`。原来深链只带 `page`，没有完整支持 `rel`。
- 修改：补了 `?page=caa_dialog&rel=...` 的 URL 同步和打开逻辑，见 [shellUrlSync.ts](../../web-ui/src/utils/shellUrlSync.ts:44)、[useAppShell.ts](../../web-ui/src/composables/useAppShell.ts:1333)。
- 理由：这样从列表、刷新、会话恢复、直接 URL 打开都能定位到具体 `.CATDlg`。

2. core 包浏览器/Node 混用
- 问题：`@phoenix/catdlg-core` 默认入口导出了 `repoRoot`，它依赖 Node 的 `fs/path/process`，浏览器端引用会有风险。
- 修改：默认入口只保留纯解析/IR 工具；新增 Node 专用入口 [node.ts](../../packages/catdlg-core/src/node.ts:1)。
- 理由：浏览器代码不应该被 Node-only API 污染。服务端则改成从 `@phoenix/catdlg-core/node` 导入 `findRepoRoot`。

3. 新建 CAA 对话框写盘
- 问题：之前 `.CATDlg` 新建格式写反了，类似 `DialogName CATDlgDialog`，而 parser 期待 `CATDlgDialog DialogName`；而且只写根节点，子控件、Grid、Spinner、NLS 都不完整。
- 修改：服务端 `/create` 改成递归从 IR 生成合法 `.CATDlg`，并收集标准 NLS key，见 [dialog.ts](../../server/caa/src/routes/dialog.ts:552)。
- 理由：保存出来的文件必须能被 parser 再读回，否则 创建成功 也会变成后续不可维护的坏文件。

4. 保存时报错/草稿丢状态
- 问题：SQL 日志显示工作台会话只保存了 `nlsFlat/nlsSourceText/localeNlsFlats`，没有保存新建草稿的完整 IR；另外保存时用 `structuredClone(ir)`，Vue 响应式对象可能触发 `DataCloneError`。
- 修改：CAA 编辑页新增 `clonePlain()`，保存时改用普通 JSON 结构克隆；草稿会话现在会保存/恢复完整 `ir/isNewDraft/draftId`，并支持关闭前 flush 草稿，见 [CaaDialogEditorPage.vue](../../web-ui/src/pages/CaaDialogEditorPage.vue:126)、[CaaDialogEditorPage.vue](../../web-ui/src/pages/CaaDialogEditorPage.vue:699)、[CaaDialogEditorPage.vue](../../web-ui/src/pages/CaaDialogEditorPage.vue:1078)。
- 理由：新建草稿拖拽后的结构必须能进入会话和草稿文件，否则刷新/关闭/保存时会回到空白或旧状态。

5. 拖拽逻辑
- 问题：拖拽逻辑原来混有大量调试输出，且跨容器 MOVE 的更新顺序容易让源/目标容器状态不同步。
- 修改：清理拖拽调试日志；跨容器 MOVE 先更新源容器，再统一 `setChildren` 同步目标、选中态和 dirty 状态，见 [CaaDialogGrid.vue](../../web-ui/src/components/caa/CaaDialogGrid.vue:269)。
- 理由：拖拽是高频操作，状态更新必须原子化、可预测；日志不能替代模型测试。

6. IR 数据结构与控件表现
- 问题：前端 IR 类型缺 `spinner`，但 parser 已能解析 `MIN/MAX/STEP/PREC`；Spinner UI 没用这些值。
- 修改：给前端 IR 补 `spinner` 类型，并让 Spinner 控件使用 `min/max/step/prec`，见 [caaDialogIr.ts](../../web-ui/src/types/caaDialogIr.ts:27)、[CaaControlSpinner.vue](../../web-ui/src/components/caa/controls/CaaControlSpinner.vue:15)。
- 理由：parser、IR、UI 三层必须一致，否则解析出来的信息会在界面层丢失。

7. 类型和属性面板结构
- 问题：部分 payload/属性面板类型没有声明实际使用字段，比如 CAA 草稿 payload 的 `isNewDraft/draftId`、`propPath.mono` 等。
- 修改：补齐 [workbench.ts](../../web-ui/src/types/workbench.ts:27)、[pageProperties.ts](../../web-ui/src/types/pageProperties.ts:73)、[pagePropertySchema.ts](../../web-ui/src/utils/pagePropertySchema.ts:124)，并把属性面板 host 改成 `shallowReactive`，避免 Vue 深层解包破坏 `ComputedRef`。
- 理由：这是 写数据结构 的部分。类型不完整时，代码看似能跑，但保存、恢复、面板渲染会埋隐患。

8. 单元测试/回归用例
- 问题：拖拽纯函数和 `.CATDlg` 声明顺序缺回归测试。
- 修改：新增 parser 顺序测试 [parseCatDlg.test.ts](../../packages/catdlg-core/src/parseCatDlg.test.ts:1)，补了 `applyDropTransform` 的覆盖/右插/下插测试 [caaDropZone.test.ts](../../web-ui/src/utils/caaDropZone.test.ts:469)。
- 理由：这些是最容易 改好一个场景、弄坏另一个场景 的逻辑，应该靠测试锁住。

9. 已有 CAA 对话框完整写回
- 问题：此前已有文件保存主要走 ROWRES/COLRES patch，只能覆盖伸缩标记这类小修改；一旦新增、删除、拖拽重排控件，就需要从 IR 重新生成 `.CATDlg`，否则界面状态和落盘文件会分叉。
- 修改：把 `.CATDlg` emit、NLS key 收集、IR 校验抽到 [emitCatDlg.ts](../../packages/catdlg-core/src/emitCatDlg.ts:1)，`/create` 和新增的 `POST /api/caa/dialog/write` 共用这套逻辑；前端按修改类型区分 `patch/full` 保存路径，见 [dialog.ts](../../server/caa/src/routes/dialog.ts:552)、[caaDialog.ts](../../web-ui/src/api/caaDialog.ts:149)、[CaaDialogEditorPage.vue](../../web-ui/src/pages/CaaDialogEditorPage.vue:1032)。
- 理由：IR 应该成为 Builder 的单一事实来源。ROWRES/COLRES patch 保留给低风险局部修改，结构变更则走完整写回，避免“看起来改了，但磁盘没真正保存结构”的漏洞。

10. 写回前校验与 dry-run 能力
- 问题：文档主线要求写回前发现 Grid 重叠、非法 FATHER、重复 id、未知控件类型，并能预览 diff；之前没有统一校验入口。
- 修改：`validateCaaDialogIrRoot()` 会在写回前返回 errors/warnings；`/api/caa/dialog/write` 支持 `dryRun`，可返回 before/after 预览文本；前端新增 [CaaDialogWritePreviewDialog.vue](../../web-ui/src/components/caa/CaaDialogWritePreviewDialog.vue:1)，编辑页提供「预览写回」按钮和弹窗确认写回。
- 理由：完整写回的风险比局部 patch 高，必须先把“明显会写坏文件”的情况挡在落盘前。现在用户能在写盘前看到当前磁盘 `.CATDlg/.h` 与 IR emit 后文本的并排预览。

11. Undo / Redo
- 问题：拖拽、添加、删除、插入行列都会直接改 IR；操作错了只能手工拖回去，尤其跨容器 MOVE 容易造成试错成本高。
- 修改：CAA 编辑页加入运行时 IR 快照栈，页头增加撤销/重做按钮，并支持 Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z；控件上下文新增 `recordHistory`，拖拽落点在真正改树前记录快照，见 [CaaDialogEditorPage.vue](../../web-ui/src/pages/CaaDialogEditorPage.vue:473)、[CaaDialogGrid.vue](../../web-ui/src/components/caa/CaaDialogGrid.vue:242)、[useCaaControlContext.ts](../../web-ui/src/composables/useCaaControlContext.ts:67)。
- 理由：Builder 类编辑器必须可逆。当前运行时保留完整编辑会话内的安全回退；后续第 32 条已补上刷新恢复最近 undo/redo 历史，并用较小上限避免 session payload 过度膨胀。

12. 多 Tab 状态收口
- 问题：全局 store 只能代表当前激活 CAA 页，多个 Tab 同时打开时，草稿 IR、选中项、dirty、编辑/预览模式容易互相串味。
- 修改：pageState 继续保存/恢复 IR、draftId、dirty，并补充 `selectedId`、`editMode`、`irWriteMode`；编辑/预览模式改为页面本地状态，不再依赖全局 Pinia `editMode`。
- 理由：这一步先把多 Tab 从“靠全局单例桥接”往 per-tab session 推了一层；后续第 31 条已补上 CAA store 按 tabId 隔离，第 32 条补上刷新后的近期 undo/redo 历史恢复。

13. CAA 索引库
- 问题：规划里的 `phoenix_caa_*` 还没落地，主页列表更像临时扫描结果，不利于后续搜索、分组、侧栏联动。
- 修改：新增 [schema.py](../../phoenix/caa/schema.py:1)、[store.py](../../phoenix/caa/store.py:1)、[caa_index_service.py](../../phoenix/services/caa_index_service.py:1)，在 Python 侧维护 `phoenix_caa_scan`、`phoenix_caa_dialog`、`phoenix_caa_dialog_group`、`phoenix_caa_dialog_group_member`、`phoenix_caa_dialog_fts`；新增 `POST /api/caa/index/scan` 和 `GET /api/caa/index/groups?q=...`，前端主页和左侧索引块改读 CAA 索引，Vite 将 `/api/caa/index` 代理到 Python。
- 理由：这更贴近原作者“Python 侧维护索引，Node 负责完整 IR parse/emit”的主线分工。CAA 搜索现在有 SQLite FTS 支撑，按 `*UI.m`/目录分组仍保留。

14. 右键删除与调试日志
- 问题：底层 `removeControl` 有了，但用户没有直接入口；拖拽期间遗留的 `console.log/console.error` 容易让开发者误把临时日志当成状态机制，也会污染高频交互调试。

- 理由：删除是 Builder 的基础操作，应该走和新增/拖拽一样的 IR 结构修改链路。日志方面，常态交互不应依赖控制台输出判断正确性，应该靠状态、校验和测试保证。
