# KT Codegen 人工点检清单

> 适用范围：Phoenix Desk Tools 的“自动代码 / KT Codegen”页面。
>
> 目标：在真实 Git 工作区中确认配置发现、独立 View、Wing 参数表、32 个控制符、预检、问题定位、配置保存和源码真实 Apply 均可用。
>
> 相关设计与安全边界：[KT-Codegen-桌面工作台.md](KT-Codegen-桌面工作台.md)

## 1. 结果约定与测试准备

每项记录“通过 / 失败 / 跳过”。失败时保留页面截图、全局运行日志、目标仓库 `git diff` 和 Desk Tools 后台日志。

清单不要求填写点检人、日期或版本等元数据。测试工作区必须由 Git 管理，建议使用可丢弃分支；需要留证据时直接保存以下命令输出：

```bash
git status --short
git rev-parse HEAD
```

准备以下样本；没有对应样本的进阶项可以标记“跳过”：

- 至少 2 个可由 Wing Reader 读取的旧 v4 JSON，验证“一份配置绑定一个 View”。
- 1 个可读取的 17 列 CSV，验证兼容读取和保存。
- 最好准备 7 个以上配置文档，验证列表最多显示 6 行后内部滚动。
- 至少 1 个包含有效 Kevin Marker 区域的 UTF-8/LF C/C++ 文件。
- 至少 1 个包含有效 Kevin Marker 区域的 GBK/CRLF C/C++ 文件。
- 一个可安全修改 Marker 的副本，用于制造不配对 Marker、外部并发修改和问题定位。

有效 Marker 应以相同的类标识和 Block 区分词成对出现，例如：

```cpp
// START KEVIN CAA WIZARD SECTION PNXExample CATALOG PARAMS
// generated area
// END KEVIN CAA WIZARD SECTION PNXExample CATALOG PARAMS
```

`START KEVIN CAA WIZARD SECTION` 与 `END KEVIN CAA WIZARD SECTION` 是配对关键字；后面的类标识和 Block 区分词必须对应。

## 2. 最小主链

这一节是每轮发布前的必测项。任何一项失败，KT Codegen 不应判定为人工验收通过。

1. 打开测试工作区，进入 Code Ribbon →“自动代码”。
2. 从左侧 Primary 选择一份 JSON 配置。
3. 修改一个参数值或表格单元格并保存配置。
4. 重新打开配置，确认保存内容已回读。
5. 只选择一个明确存在于测试源码中的控制符并执行“预检”。
6. 在下方面板核对“当前源码”和“Wing 生成候选”。
7. 执行“Apply 源码”，再用 Git 检查真实写盘结果。

- [ ] Ribbon 当前入口显示“自动代码”并呈选中态
- [ ] JSON 正确打开，类名、参数表和行数与磁盘内容一致
- [ ] 编辑后 Tab、标题或活动文档出现 `*`，保存后消失
- [ ] 保存后关闭并重新打开，修改值仍然存在
- [ ] 预检能找到预期 Marker，显示区域、Artifact 和诊断数量
- [ ] 下方面板在当前工作台内部显示，没有另开并列 View
- [ ] Apply 真实修改目标源码，不是 dry-run
- [ ] `git diff` 只包含预期配置或 Marker 区域变更
- [ ] 运行日志记录预检、Apply 文件数、区域数和写回结果

## 3. Header、Primary、右栏和全局下方面板

- [ ] Code Ribbon 入口顺序与设计一致：Code 索引、忽略设定、C++ 成员排序、Code 批量改名、Code UUID 替换、自动代码、CAA 对话框
- [ ] 当前“自动代码”入口使用绿色选中态，其他入口没有误高亮
- [ ] Header 右侧没有左/下/右三面板控制按钮；只保留 Ribbon 单行/双行切换
- [ ] Footer 右侧只显示左、下、右三个 VS Code 风格面板按钮
- [ ] Footer“左”只控制当前页面 Primary；关闭后主 View 正常扩展
- [ ] Footer“下”只控制全局下方面板；再次打开仍保留高度和当前页签
- [ ] Footer“右”控制固定在右侧的工作空间树和页面属性
- [ ] 工作空间树与页面属性始终在右侧，不因切换页面跑到左侧
- [ ] 下方面板拖拽句柄可以调整高度，内容区不会被挤成负高度
- [ ] 切到其他页面后下方面板实例不消失；“运行日志”仍保留全局内容
- [ ] “预检”“问题”“运行日志”三个页签均可切换，内部内容可独立滚动

## 4. 配置发现、过滤与独立 View

- [ ] 左侧“配置文档”只列出 Wing 能完整识别的 JSON/CSV，普通 JSON/CSV 不误入列表
- [ ] 点击“刷新”会重新发现配置；扫描中按钮变为“取消”，取消后界面可继续操作
- [ ] 过滤框可按文件名、类名、路径和格式过滤，清空后恢复完整列表
- [ ] 配置文档超过 6 个时列表只显示 6 行高度，并出现列表内部垂直滚动条
- [ ] 配置列表滚动不带动整个 Primary 跳走
- [ ] 点击配置 A 打开 View A；点击配置 B 新开 View B，不复用 A 的 View
- [ ] View A、View B 分别绑定各自 JSON/CSV，标题、副标题、参数和 dirty 状态互不串联
- [ ] 再次点击已经打开的配置 A，只激活原 View A，不创建重复 View
- [ ] 第一次从 Ribbon 进入产生的空 View，在选择首份配置时被直接绑定，不残留无意义空 Tab
- [ ] 在 KT Codegen 激活时，从工作空间树点击有效 JSON/CSV，行为与左侧列表一致
- [ ] 切换、关闭或重新打开 View 时，不会把 A 的表格内容保存到 B
- [ ] 配置被删除、忽略或暂时未被后台刷新命中后，已经打开且 dirty 的 View 仍保留
- [ ] 后台 15 秒刷新不会抢焦点、覆盖当前草稿或反复读取未变化配置

## 5. 活动文档属性、Wing 表格与控制符

- [ ] Prefix、Middle、Namespace、Append 显示当前配置真实值
- [ ] 修改任一活动文档属性后立即出现 dirty 标记，Header 类名摘要同步变化
- [ ] Wing 参数表显示正确列、行数和已有内容，横向或纵向内容可滚动查看
- [ ] 修改任一表格单元格后立即出现 dirty 标记，旧预检同时失效
- [ ] 连续修改多个单元格时，每次修改都进入当前草稿，不只记录第一次变化
- [ ] 控制符标题显示 `已选数量 / 32`，列表内部有垂直滚动条
- [ ] 控制符过滤可匹配旧 ID、Block Key、控制词、平台和 deprecated 状态
- [ ] “全选”“清空”“C++”“Field”结果与 Wing 预设一致，重复点击状态稳定
- [ ] 开启“单选”后最多保留一个控制符；点击另一个控制符会替换当前选择
- [ ] 关闭“单选”后可恢复多选
- [ ] deprecated 控制符有明确标签，但不会因展示标签改变真实 Block Key
- [ ] 切换配置 View 后，每个 View 的参数、表格和控制符选择保持独立

## 6. Marker 配对与错误诊断

先用 Git 管理的测试副本进行以下修改，不要破坏无法恢复的生产源码。

- [ ] 正常的 `START ... <classId> <block discriminator>` 与对应 `END ...` 被识别为一对
- [ ] 同一对 Marker 后面的类标识和 Block 区分词一致时，不出现 `marker.unknown-block`
- [ ] `START KEVIN CAA WIZARD SECTION` / `END KEVIN CAA WIZARD SECTION` 本身不会被误当成 Block 名
- [ ] 32 项之外但正确成对的旧辅助 Marker 保持原样，不产生伪 `marker.unknown-block` 诊断
- [ ] 只有目标生成 Block 进入 Plan；不同 Block 的区分词不会互相串配
- [ ] 删除一个 END 或改错类标识后，“问题”出现明确 error/warning，Apply 安全门禁关闭
- [ ] 恢复正确 END 后重新预检，旧错误消失且区域重新可 Apply
- [ ] Reader 兼容诊断同时能在配置行和“问题”页签中看到

## 7. 预检、候选源码和问题定位

- [ ] 点击“预检”后按钮变为“取消预检”，取消能终止本轮请求且不会沿用旧结果
- [ ] 预检期间再次刷新、切换工作区或更换配置，不会让旧响应覆盖新页面状态
- [ ] 左侧显示候选源码数量、Marker 首行、编码和换行类型
- [ ] 候选源码过滤只影响列表展示，不改变实际 Plan
- [ ] 点击候选源码后，“预检”页签显示对应只读源码片段
- [ ] 点击“预检命中”区域后，当前源码与对应 Wing Artifact 联动
- [ ] Artifact 列表、当前源码、Wing 生成候选三个小区域均有自己的滚动能力
- [ ] 当前源码显示正确文件、行号、编码和 LF/CRLF
- [ ] “可 Apply”时区域数、产物数和计划指纹可见
- [ ] 有诊断或扫描不完整时显示“安全门禁未通过”，不伪装成可 Apply
- [ ] “问题”按 error/warning/info 显示级别、代码、消息、来源和路径位置
- [ ] 点击带源码行位置的问题后自动切到“预检”，定位到正确文件和行
- [ ] 定位行使用黄色背景和左侧黄色标识；不是普通蓝色选中态
- [ ] 没有可定位源码位置的问题不可点击，不会打开错误文件
- [ ] 同样的配置、控制符和未变化源码再次预检时可看到缓存复用，结果与首次一致

## 8. 配置保存、还原、会话恢复与外部冲突

### 8.1 JSON / CSV 保存

- [ ] 修改 JSON 后点击“保存 JSON”，按钮有进行态且保存期间不能切换文档
- [ ] 保存完成后重新打开 JSON，Wing Reader 能完整回读且 dirty 消失
- [ ] 修改 CSV 后按钮显示“保存 CSV”，保存后仍保持 17 列格式并可重新读取
- [ ] 配置原有 UTF-8、UTF-8 BOM 或 GBK 编码按支持边界正确保留
- [ ] 保存只修改目标配置，不生成残留临时文件
- [ ] 点击“还原”会重新读取磁盘版本并清除未保存修改
- [ ] clean 且磁盘未变化时“还原”不可误操作

### 8.2 外部修改与会话

- [ ] clean View 对应配置被外部修改后，页面自动载入磁盘新版本
- [ ] dirty View 对应配置被外部修改后显示冲突提示，不静默覆盖本地草稿
- [ ] 冲突状态可复制当前草稿，再从磁盘重载
- [ ] 外部删除活动配置时仍保留当前 View 和草稿，并明确显示文件已删除
- [ ] 保存前由外部进程替换文件、改权限或改正文时返回冲突，不覆盖外部版本
- [ ] 有未保存修改时重启 Desk Tools，磁盘指纹未变则恢复正确配置、表格和控制符
- [ ] 重启前磁盘内容已变化时不自动套用旧草稿；显示“旧草稿未自动恢复”
- [ ] 恢复冲突时可以复制旧草稿或明确放弃，未处理前不能保存或 Apply
- [ ] 关闭 dirty View 时存在保存/放弃/取消门禁，不直接丢失修改

## 9. 源码真实 Apply 与 Git 验证

这一节必须在 Git 可恢复的测试工作区执行。`Apply 源码` 是真实写盘，不是 dry-run。

执行前记录：

```bash
git status --short
git diff -- path/to/target.cpp
```

- [ ] 没有手工预检时直接点击“Apply 源码”，会先自动预检再决定是否写盘
- [ ] 有旧预检时点击 Apply 仍强制重跑当前 Param、Table、Block 和源码的预检
- [ ] Apply 只写入与 Artifact 唯一匹配的 Marker 区域
- [ ] 同文件多个区域均写入正确位置，后一个区域没有因前一个替换发生偏移
- [ ] UTF-8/LF 文件写回后仍为 UTF-8/LF
- [ ] UTF-8 BOM 文件写回后仍保留 BOM
- [ ] GBK/CRLF 文件写回后仍为 GBK/CRLF，中文没有乱码
- [ ] 文件权限保持不变
- [ ] “运行日志”列出实际写入文件、区域数、编码/换行或最终结果
- [ ] Apply 后重新预检，生成结果与磁盘内容一致
- [ ] 对已经一致的结果再次 Apply 为 no-op，不产生无意义 diff 或改变文件时间
- [ ] Apply 后目标仓库 `git diff` 只包含预期 Marker 区域
- [ ] Apply 过程没有在目标目录残留临时文件

完成主链后记录：

```bash
git status --short
git diff --stat
git diff -- path/to/target.cpp
```

确认结果后可按测试仓库约定提交；不保留测试结果时，用 Git 恢复本轮明确修改过的文件。

## 10. Apply 并发保护与失败回滚（进阶）

- [ ] 预检后外部修改任一目标源码，5 秒内旧 Plan 被标记失效或清除
- [ ] 预检后修改 Param、表格或控制符，旧 Plan 立即失效
- [ ] Apply 前瞬间修改目标源码时服务端拒绝写入，不使用前端旧 Plan
- [ ] 预检后删除目标源码，Apply 明确失败且不创建替代文件
- [ ] Marker 区域重叠、偏移异常或 Artifact 无法唯一对应时拒绝 Apply
- [ ] 构造多文件写回并使后一个文件失败：先前已提交文件自动回滚到原字节
- [ ] 回滚前若文件又被外部修改，工具拒绝覆盖该外部修改并明确报告路径
- [ ] 源码扫描达到 5000 文件或 64 MiB 快照上限时仍可看部分结果，但 `safe_to_apply=false`
- [ ] 扫描不完整时前端 Apply 被关闭，直接调用后端也不能绕过门禁
- [ ] 在 Code Ignore 排除无关目录后重新预检，扫描完整时才恢复可 Apply

## 11. 多 View、全局日志与页面切换

- [ ] 同时打开配置 A、B 并分别预检，切换 View 时下方面板切换到对应文档的预检/问题上下文
- [ ] A 的预检结果不会出现在 B 的“预检”中，B 的问题不会污染 A
- [ ] 切回 A 后原候选、区域、Artifact 和选中位置仍在
- [ ] “运行日志”汇总所有模块日志，不因切换 View 或页面被清空
- [ ] 点击“清空”只清除运行日志，不清除配置、预检或问题
- [ ] 切到 CAD、CAA 或其他 Code 页面后，运行日志仍固定在下方面板，不出现在右栏
- [ ] 页面没有预检贡献时，下方面板显示明确空状态，不显示错误页面的旧控件
- [ ] 收起下方面板后执行普通操作不会强制打开；需要定位问题时可自动展开到正确页签

## 12. 空状态、忽略规则与异常输入

- [ ] 未选择工作区时有明确提示，不发起无意义扫描
- [ ] 工作区没有 Codegen 配置时显示“未发现配置”，Primary 和 View 不报错
- [ ] 工作区只有普通 JSON/CSV 时不会被误识别为 Codegen 配置
- [ ] 配置路径含中文、空格和多级目录时可发现、打开、保存和回读
- [ ] Code Ignore 内置规则、`.phoenix/code.ignore` 和工作区自定义规则对候选源码生效
- [ ] 被忽略目录中的 Marker 不进入候选和 Plan
- [ ] 配置格式损坏、字段缺失或超过大小限制时显示结构化诊断，不导致页面白屏
- [ ] 源码解码失败时显示文件路径和明确问题，不写入乱码
- [ ] 快速连续点击刷新、预检、切换配置和切换工作区后，最终界面只对应最后一次用户选择
- [ ] 网络/API 失败后按钮恢复可操作，运行日志保留错误信息，可重新尝试
