> 关联：[改名与XLink引用修正-规划讨论.md](改名与XLink引用修正-规划讨论.md)、`fix_fcstd_xlink_paths.py`、`fcdesk/services/xlink_fix_service.py`

---

## 1. 问题

批量脚本 `fix_fcstd_xlink_paths.py` 在 XLink 无法相对宿主解析时，用 **basename** 查 CAD 索引映射。若映射中无该文件名（`verdict=未找到`），脚本**不写回**。

典型场景：装配仍引用 `8003.001-H-PHOENIX-滑轨.FCStd`，实体已改名或仅在索引中以**同 Part Key、不同文件名**存在。

---

## 2. 与自动「可修正」的区别

| 状态 | 数据来源 | 写回方式 |
| --- | --- | --- |
| **可修正** | 脚本 `pick_target` 已选好 `new_path` | 页内「执行修正」批量跑脚本 |
| **未找到** | 映射无 basename | **行展开** → 按 Part Key 选手动目标 →「修正此项」 |

手选写回不走批量脚本，而使用改名分析同款逻辑：

- `preferred_xlink_attr_for_target(host, target_repo_rel)` 计算新 `file="…"`
- `patch_fcstd_xlink_attrs(host_fcstd, { old_path: new_path })` 按 **完整旧 attr 字符串** 替换

---

## 3. 交互（行展开，优先）

仅 **`status=not_found`** 且能推断 Part Key 的行可展开。

1. 点击行首 **▶** 或整行（未找到行）展开子区域。
2. 子区域展示：
   - 推断 **Part Key**（`hints_from_fcstd_filename` → `PartNumber` + `PartVersion`），可跳转零件详情 Tab。
   - **候选 FCStd**：`GET /api/part-keys/{pn}/{pv}`，仅列出 `file_status=present` 且扩展名为 `.fcstd` 的关联文件。
3. 单选候选 → **「修正此项」** → `POST /api/xlink-fix/apply-override`。
4. 成功后该行变为可修正态（展示 `new_path`），统计可重新「分析」刷新。

无法推断 Part Key 时，展开区提示手动在 CAD 索引 / 零件目录中查找。

---

## 4. Part Key 推断规则

自 XLink 的 `file` 属性 **basename** 解析（`infer_part_key_from_filename`）：

- 前缀 **`编号.版本`**，版本 **2–3 位**（如 `.001`、`.01`→`001`），后接 **`-` 或 `_`**
- **零件号不必六位**：`8003.001-H-…` → Part Key **`8003.001`**（`8003` + `001`）
- 去掉 **`.Drawing`** 后再解析（图纸 FCStd）
- 推断失败时：`GET /api/xlink-fix/candidates?basename=…` 另按 **文件名 / 主干前缀** 在 `file_asset` 中搜 present 的 FCStd

## 5. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/xlink-fix/analyze` | `issue_rows[]` 含 `part_number`、`part_version`、`part_key` |
| GET | `/api/xlink-fix/candidates` | Part Key 关联 + basename 回退候选 |
| GET | `/api/part-keys/{pn}/{pv}` | 与 candidates 内部一致，页面优先调 candidates |
| POST | `/api/xlink-fix/apply-override` | 体：`host_repo_rel`、`old_path`、`target_repo_rel` |

`apply-override` 响应示例字段：`patches`、`new_path`、`target_repo_rel`、`target_display`。

## 7. 与文件详情「引用关系」的差异

| | 文件详情 · 出向 | 链接路径修正 |
| --- | --- | --- |
| 数据来源 | `bom_xref`（打开/刷新时对该 FCStd **从磁盘重读** XLink） | 扫描目录内 FCStd，仅汇报 **需改写** 的 `file` 属性 |
| 仍显示「缺失」 | 索引中无目标 / 歧义，或尚未刷新 | 不在问题列表：路径已能相对宿主解析、或宿主不在扫描范围 |
| 写回后 | 手选/批量写回后会 **刷新对应宿主的 bom_xref**；文件详情点「重建本文件引用索引」或「刷新列表」 |
| 仅本文件多级索引 | **重建本文件引用索引**（可选「含下级 FCStd」）→ `POST /api/bom-xrefs/refresh-host-index`（`fcdesk.services.cad_index`）；不重扫 CAD 属性，出向 **缺失/歧义** 高亮 |
