# 内部装配示例 — BOM 挂载节点错误分析

> **样例**：[`内部装配示例-Document.xml`](内部装配示例-Document.xml)  
> **现象**：属性回写 / 改名写 Label 时，BOM 挂到 **`_6222656233`**，Label 为 `8008.001-内部装配`；**不是**总成根节点。  
> **状态**：问题确认（当前规则下可复现）；**未改代码**。

---

## 1. 现象

| 位置 | Label / BOM | 是否应为「产品/总成」挂载点 |
|------|-------------|---------------------------|
| **Document** | `8008.001-H-PX-内部装配` | ✅ 文件级名称（正确语义） |
| **`_6222656233`**（`App::Part`） | `8008.001-内部装配` + PartNumber `8008` / PartVersion `001` / PartName `内部装配` / TypeCode `H` / ModelSeries `PX` | ❌ **fcdesk 当前写入点**（叶子包装容器） |
| **`PCB`**（`App::Part`） | `8008.001`（无 CustomDefine BOM 四项） | ✅ **模型树顶组**（Group → C6/C4/C2） |
| **`C6` / `C4` / `C2`** | `C6` 等 | 子装配/子区域容器 |

用户在 FreeCAD 里若用 fcdesk **写入属性** 或 **改名同步 Label**，会改 **`_6222656233`** 上的 Property，与树顶「内部装配」产品身份不一致。

---

## 2. 模型树（本文件真实结构）

本样例为 **纯内部装配**（无 `<XLink file="…fcstd"/>`），多个 **就地 `App::Part` 容器** 嵌套：

```
Document  Label: 8008.001-H-PX-内部装配
└─ PCB (App::Part)          Label: 8008.001
   ├─ C6 (App::Part)        Label: C6
   │  └─ _6222656233        Label: 8008.001-内部装配  ← BOM 属性实际写在这里
   │     └─ Part__Feature025  Label: Extruded016
   ├─ C4 (App::Part)
   │  └─ _6222656234 → Part__Feature026 …
   └─ C2 (App::Part)
      └─ _6222656235 → Part__Feature027 …
```

- **`PCB`**：`Group` = `C6`, `C4`, `C2` — **整机关联根**。  
- **`_6222656233`**：仅为 **C6 下包住一个 Extrude 特征** 的 FreeCAD 自动命名容器（`OriginGroupExtension`），**不是**整机总成。

---

## 3. 根因：fcdesk 挂载规则

实现：`fcdesk/freecad/fcstd_document_bom_props.py` → `_first_bom_target_object_name`：

1. 第一个 `PartDesign::Body`  
2. 否则第一个 `type` 含 `assembly`  
3. 否则 **第一个 `App::Part`（按 `<Objects>` 声明顺序）**  
4. 否则图纸-primary 时第一个 `App::Link`

本文件：

- 无 `PartDesign::Body`、无 Assembly 类型名；  
- **第一个** `App::Part` = **`_6222656233`**（在 XML 里排在 `C6`、`PCB` **之前**）；  
- 故读写 BOM、读嵌入式属性、改名写 Label 均指向该节点。

本地验证：

```text
_first_bom_target_object_name(doc) → "_6222656233" (App::Part)
```

**问题本质**：用 **扁平 Object 列表顺序** 选「第一个 Part」，**未看 Group 父子**，把 **深层叶子包装 Part** 当成 **文件级 BOM 挂载对象**。

这与 [FreeCAD-BOM概念与数据模型-研究.md](../FreeCAD-BOM概念与数据模型-研究.md) §2.4「本地零件 / 非 Link 子件」一致：内部多层 `App::Part` 时，**第一个 Part ≠ 产品根**。

---

## 4. 受影响能力

| 功能 | 错误表现 |
|------|----------|
| **属性回写** `save_bom_to_fcstd` / `read_embedded_bom_attrs` | 读写到 `_6222656233`，非 `PCB` |
| **文件详情 · 属性** | 展示/保存的 Document.xml 字段来自错误 Object |
| **CAD 索引扫描** | 若从 Document 读 BOM，可能读到子容器上的 8008/001（与 Document Label 的 H/PX 组合不一致） |
| **改名 · Label 同步** | `resolve_rule_display_label` / XLink Label 写回若绑定挂载对象，会改错节点（本文件无 XLink，主要伤属性） |
| **`bom_xref`** | 无外部 XLink，**不进引用表**；BOM 结构表仍空 — 与挂载错误是 **并列** 问题 |

Document 级已有 Label `8008.001-H-PX-内部装配`，与 `_6222656233` 上 `8008.001-内部装配`（缺 H、顺序不同）**并存**，易造成索引与界面不一致。

---

## 5. 期望挂载点（产品语义）

对本样例，更合理的 **单一 BOM 挂载对象** 候选（择一，需产品规则拍板）：

| 优先级 | 对象 | 理由 |
|--------|------|------|
| **A** | **`PCB`** | 唯一包含 C6/C4/C2 的顶 `Group`；树顶「整机」 |
| **B** | **Document Properties** 的 Label + 单独约定 PartNumber 存 Document（FreeCAD 惯例部分团队这样做） | 与文件名 `8008.001-H-PX-内部装配` 一致 |
| **C** | 名称匹配文件名/Document Label 的 `App::Part` | 启发式，避免 `_622265623*` 随机名 |

**不应**再选：`_6222656233`、`_6222656234`、`_6222656235`（均为子区域几何包装）。

## 6. 后续改法方向（Todo，未实现）

1. **结构感知选根**：在 `App::Part` 候选中，优先 **不被任何其它 `App::Part.Group` 引用的 Part**（入度 0）；多根时再比 **Group 子节点数** 或 **名称非 `_` 随机前缀**。本例唯一根 → **`PCB`**。  
2. **排除包装 Part**：`Group` 仅 1 子且子为 `Part::Feature` / 单 Body 的 Part，降级为「几何包装」，不参与文件级 BOM 竞争。  
3. **与 Document Label 对齐**：挂载对象 Label / PartKey 应与 `Document.Label` 或文件名推断一致时再采纳。  
4. **回归样例**：本 XML 加入测试 — `assert mount == "PCB"`（或你们定的根名）。  
5. **已有错误数据**：工程里已写在 `_6222656233` 的 CustomDefine 属性，修复代码后需 **迁移或重新回写** 到 `PCB`（用户手工或一次性脚本）。

## 7. 与「内部装配 / 非 Link BOM」的关系

- 此文件 **没有** Link 子件 → **无** `bom_xref` 边 → Web **装配结构 / 出向引用** 为空是预期，不是挂载 bug。  
- 挂载 bug 只影响 **PartKey / 属性 / Label** 落在 **哪个 DocumentObject**。  
- 若未来要对「内部子件 C6/C4/C2」做 MBOM，需 **另建规则**（按 Group 展开虚拟行），与本次「文件级挂载」分开。
